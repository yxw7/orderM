# 导入任务详情 — 预览核对上下主从布局

**日期**：2026-07-10  
**状态**：已评审待实现  
**模块**：采访验收 / 导入任务详情  
**关联规格**：
- [2026-07-10-delivery-import-async-task-design.md](./2026-07-10-delivery-import-async-task-design.md)（任务流程、Tab 提交、自动保存等）
- [2026-06-23-delivery-note-import-acceptance-design.md](./2026-06-23-delivery-note-import-acceptance-design.md)（§7.1 订单行 16 列、§9.4 处置校验）

---

## 1. 背景与问题

当前任务详情预览采用 **主表行内展开子表**：子表列 = 馆址 + 订单行号 + 已映射字段 + 待收 + 5 列处置字段。存在以下问题：

1. 用户需要在核对时看到与「选择订单行」弹窗一致的 **完整 16 列**订单行信息。
2. 若将 16 列与 6 列处置字段全部放入行内宽表，列数约 22 列，横向滚动严重，多馆址子行时纵向空间膨胀。
3. 信息展示与处置编辑混在同一表格，核对效率低。

---

## 2. 目标

- 上区：发货主行列表，支持 Tab 过滤、分页、批量勾选提交。
- 下区：展示 **当前选中发货行** 的馆址订单行，以 **卡片** 形式呈现 **16 列完整信息 + 单列处置表单**。
- 去掉主表行内展开子表。
- 下区支持 **追加 / 批量删除** 订单行（复用选行弹窗）。
- 沿用现有校验、400ms 防抖自动保存、已提交只读规则。

## 3. 非目标

- 发货单 vs 订单行字段差异标红（原 spec 后续迭代）。
- 可拖拽上下分隔条（本期固定 60% / 40%）。
- 修改主行匹配状态重算逻辑（仍不重算）。

---

## 4. 方案选型

| 方案 | 说明 | 结论 |
|------|------|------|
| **A. 上下主从 + 卡片** | 上 60% 发货列表，下 40% 订单行卡片 | **采用** |
| B. 左右分栏 + 卡片 | 左列表右卡片 | 不采用；主表字段多时左侧过窄 |
| C. 行内展开 + 冻结列 | 保留展开，分区冻结 | 不采用；22 列体验仍差 |

---

## 5. 整体布局

```
┌─────────────────────────────────────────────────────────────┐
│ 面包屑 + 验收单/任务信息（不变）                              │
├─────────────────────────────────────────────────────────────┤
│ 状态 Tab + 提交按钮（不变）                                   │
├─────────────────────────────────────────────────────────────┤
│ ▲ 上区 60%（独立纵向滚动）                                    │
│ [√] 序号 状态 | 已映射字段… | 发货套数 | 子行数 | 操作(删除)  │
│ 分页                                                          │
├─────────────────────────────────────────────────────────────┤
│ ▼ 下区 40%（独立纵向滚动）                                    │
│ [添加订单行]  [删除订单行]                                     │
│ ┌─ [√] 卡片：华威桥 · st001-3 ─────────────────────────────┐ │
│ │ 16列网格(左)          │  处置表单(右，单列)                │ │
│ └──────────────────────────────────────────────────────────┘ │
│ ┌─ [√] 卡片：城图 · st001-4 ───────────────────────────────┐ │
│ └──────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

### 5.1 分区高度

| 区域 | 高度 | 滚动 |
|------|------|------|
| 上区 | **60%** 预览区可用高度 | 表体独立滚动；分页固定在上区底部 |
| 下区 | **40%** | 卡片列表独立滚动 |

### 5.2 选中联动

- 点击上区某发货行 → **高亮**该行，下区刷新为该行的子订单行卡片。
- 上区翻页 / 切换 Tab 后：默认选中 **当前页第一条**（可编辑 Tab 下优先第一条未提交行）。
- 未选中任何发货行时，下区展示空态：「请从上方选择一条发货记录」。
- 点击发货行后，页面 **平滑滚动** 使下区进入视口（`scrollIntoView`）。

### 5.3 下区顶栏

- **不展示**发货行摘要（无题名/ISBN/发货套数等重复信息）。
- 可编辑态显示：
  - **添加订单行**
  - **删除订单行**
- 只读态（已提交 Tab / 任务已完成或已取消）：隐藏上述按钮；卡片无勾选框。

## 6. 上区：发货主行列表

### 6.1 列定义

| 列 | 说明 |
|----|------|
| 勾选 | 批量提交用（只读 Tab 隐藏） |
| 序号 | |
| 状态 | 匹配成功 / 部分收货 / 匹配失败 / 超收 |
| 已映射展示字段 | 按任务 `mappingConfig` + `fileColumns`（`getPreviewDisplayColumns`） |
| 发货套数 | 若已映射 `receiveQty` 则独立列 |
| 子行数 | 如 `2 馆址`；无子行显示 `0 馆址` |
| 操作 | **仅「删除」**（删除整条发货主行） |

**移除**：展开列、「选择订单行」。

### 6.2 交互

- 行点击（非勾选、非删除）→ 选中并驱动下区。
- 选中行视觉：背景高亮（如 `bg-sky-50`）+ 左侧强调线。
- 删除发货主行：确认后移除；若该行正被选中，下区回空态。

---

## 7. 下区：订单行卡片

### 7.1 卡片结构

每张卡片对应 **一条馆址订单行**，横向三区：

| 区 | 宽度建议 | 内容 |
|----|----------|------|
| 勾选 | 固定 | 复选框，供「删除订单行」批量操作 |
| 信息区 | ~60% | 16 列描述网格（4 列 × 4 行） |
| 处置区 | ~35% | 单列纵向表单 |

**卡片标题行**（信息区顶部）：`馆址 · 订单行号`

### 7.2 信息区 — 16 列

与 [§7.1 选择订单行弹窗](./2026-06-23-delivery-note-import-acceptance-design.md#71-选择订单行弹窗) 完全一致，复用：

- `PICK_ORDER_LINE_COLUMNS`
- `formatPickOrderLineDisplayRow`

| 列 | 列 | 列 | 列 |
|----|----|----|-----|
| 订单号 | 馆址 | 订单行号 | 正题名 |
| 资源标识 | 载体 | 作者 | 出版社 |
| 出版时间 | 定价 | 币种 | 套内册数 |
| 套数 | 行状态 | 验收状态 | 发/收/换/退/撤订 |

- 字体 `text-xs`；过长字段 `truncate` + `title` 悬停全文。
- 默认 **全部展开**，不折叠。

### 7.3 处置区 — 单列表单

纵向排列（标签 + 控件）：

| 字段 | 控件 | 说明 |
|------|------|------|
| 待收套数 | 只读文本 | |
| 收货套数 | 数字输入 | 可编辑态 |
| 换货套数 | 数字输入 | |
| 换货原因 | 下拉 | 换货 > 0 必填 |
| 退货套数 | 数字输入 | |
| 退货原因 | 下拉 | 退货 > 0 必填 |

只读态：全部改为纯文本。

### 7.4 下区操作

#### 添加订单行

1. 打开 `DeliveryImportPickOrderLineModal`（复用 §7.1 弹窗）。
2. 用户在弹窗中多选订单行，确定后 **追加** 到当前发货行的子行列表。
3. **去重**：已存在的 `orderLine` 不重复追加。
4. 对全部子行（含新增）按原 spec **§6.1** 重新分配套数（发订时间由远到近）。
5. **不重算**主行匹配状态。
6. 触发 400ms 防抖自动保存。

> 与旧「选择订单行」差异：语义为 **追加**；若业务需「替换全部子行」，可在实现阶段增加二次确认，本期默认追加。

#### 删除订单行

1. 卡片左侧勾选一条或多条子行。
2. 点击顶栏 **「删除订单行」**。
3. 未勾选时提示「请至少选择一条订单行」。
4. 确认后移除所选子行；**其余子行处置值保持不变**（不自动重跑 §6.1）。
5. 若删至 0 条子行，提交校验仍按「匹配失败且无子行」处理。
6. 触发自动保存。

## 8. 数据与接口

### 8.1 子行数据结构（扩展）

每条 `child` 除现有处置字段外，需能还原 16 列展示：

| 字段 | 说明 |
|------|------|
| `lineNo` | 订单行号 |
| `location` | 馆址 |
| `orderLineData` | 原始订单行对象（匹配/选行/追加时写入） |
| `fieldValues` | 已映射字段（预览主表用，保留） |
| `pending` / `receive` / `exchange` / `ret` / 原因 | 现有处置字段 |

展示时：`formatPickOrderLineDisplayRow(child.orderLineData)`；若仅有 `fieldValues` 则降级展示映射字段 + 馆址/行号。

### 8.2 匹配 / 选行 / 追加时

- 从 `getMatchableOrderLines(ctx)` 或弹窗选中行写入完整 `orderLineData`。
- `buildChildrenFromPickedLines` 等 helper 需同步扩展。

### 8.3 草稿与 API

- 自动保存、提交前 flush 行为 **不变**（见异步任务 spec §9.3）。
- `childrenDraft` JSON 含 `orderLineData` 快照。

## 11. 测试要点

1. 上区 60% / 下区 40%，各自独立滚动，互不遮挡分页。
2. 点击上区行 → 下区刷新卡片；翻页后默认选中第一条。
3. 下区 **无**发货行摘要；顶栏仅有「添加订单行」「删除订单行」。
4. 卡片展示 16 列，与选行弹窗字段一致。
5. 处置区为 **单列** 纵向表单；修改后 400ms 自动保存。
6. 添加订单行：追加、去重、§6.1 重分配；主行状态不变。
7. 删除订单行：勾选多条 → 顶栏批量删除；剩余子行处置保留。
8. 上区操作列 **仅删除**；删除发货主行后下区空态。
9. 已提交 Tab：下区只读，无勾选与按钮。
10. 子行数为 0 时上区显示 `0 馆址`；提交校验提示正确。

## 12. 决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 布局 | 上下 60% / 40% | 全宽展示 16 列；比左右分栏更适合宽表 |
| 子行展示 | 卡片 + 16 列网格 | 与选行弹窗对齐；避免 22 列宽表 |
| 处置布局 | 卡片右侧单列表单 | 编辑字段清晰，不挤占信息区 |
| 下区摘要 | **不展示** | 避免与上区重复 |
| 选行语义 | **添加订单行**（追加） | 用户明确 |
| 删行交互 | 卡片勾选 + 顶栏批量删 | 用户选 B |
| 上区操作 | 仅删除发货主行 | 用户明确 |
