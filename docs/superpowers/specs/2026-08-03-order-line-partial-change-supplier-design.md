## 1. 背景与目标

用户需对单条订单行按**部分或全部可迁出套数**更换供应商（并可改预算）：迁出套数进新待发订订单，原行仅对迁出套数记撤订。入口改到行操作列；原工具栏「更换供应商」去掉，后续以批量导入形式另做。

### 1.1 目标

- 行操作「更换供应商」：满足条件时显示；打开弹窗可改「套数」及供应商/预算等
- 套数默认 = 可迁出；须为 1～可迁出的整数
- 按填写套数建新单/新行，并回写原行撤订段

### 1.2 非目标

- 工具栏批量勾选更换供应商
- Excel/CSV 批量导入更换供应商（见批量导入规格）
- 改造催缺管理「更换供应商」
- 真实后端；前端 mock 写 order store

---

## 2. 方案

**扩展现有弹窗 + 入口改行操作（已选）**

- 去掉工具栏「更换供应商」按钮
- 操作列条件显示「更换供应商」
- 弹窗在表单中增加「套数」「原因」字段（布局：订单名称 → 套数 → 供应商 → 预算 → 原因 → 备注）
- 提交逻辑由「全量未收货」改为「用户指定套数」

---

## 3. 入口与显示条件

| 项 | 约定 |
|----|------|
| 位置 | 订单行列表操作列（与查重/编辑/撤订同级） |
| 文案 | 更换供应商 |
| 工具栏 | **不提供**本期更换供应商按钮 |

**显示条件（全部满足才显示）**

1. 行状态（lineStatus）∈ {已发订, 处理中}
2. 验收状态（acceptanceStatus）∈ {待验收, 部分收货, 换货中}
3. 可迁出套数 ≥ 1

**不再**以是否催缺（isShortage）限制显示：已催缺行只要满足上列条件也可走行内更换。

---

## 4. 可迁出套数

解析发/收/换/退/撤订（flowStats）后：

```text
可迁出套数 = max(0, 发订 − 已收 − 已退 − 已换)
```

提交前重新计算；若填写套数 > 当前可迁出，则提示并中止。

---

## 5. 弹窗

复用现有更换供应商弹窗结构（FormModal）。

弹窗顶部（订单名称上方）只读展示当前行流转套数：`发订套数：N 已收货套数：N 已换货套数：N 已退货套数：N`（解析 flowStats；发订为空时回退行套数）。

| 字段 | 表单标签 | 必填 | 说明 |
|------|----------|------|------|
| 订单名称 | 订单名称 | 是 | 默认 `{原订单名}-{max+1}`（扫描已有「原名-数字」），可改；提交不校验重名 |
| 迁出套数 | **套数** | 是 | 打开时默认 = 可迁出；整数，1 ≤ 值 ≤ 可迁出 |
| 供应商 | 供应商 | 是 | 默认带入原订单供应商；按原订单采选方式过滤选项，可改 |
| 预算名称 | 预算名称 | 条件必填 | 默认带入原订单预算；交换/捐赠可空，其余必填 |
| 原因 | 原因 | 是 | 下拉；取「退换撤订原因参数」中类型为撤订且使用中的原因 |
| 备注 | 备注 | 否 | 打开时默认带入原订单行备注（remark），可改；写入新订单备注类字段 |

- 标题：更换供应商  
- 确认：生成新订单  
- 继承（不编辑）：订户、馆址、资源类型、语种、采选方式、折扣等取自原订单  
- 新订单状态：待发订；恰好 1 条新订单、1 条新订单行  

---

## 6. 提交数据流

1. 校验表单与套数范围。  
2. 新建订单头（继承 + 弹窗覆盖字段）。  
3. 新建订单行：套数与发订段 = 填写的套数；flowStats = `{套数}/0/0/0/0`；行状态待发订；是否催缺 = 否；书目字段自原行复制。  
4. 回写原行（不打开撤订原因弹窗）：  
   - 撤订段 += 本次套数；原因 = 弹窗所选原因  
   - 按更新后 flowStats 重算行状态/验收状态（复用现有部分撤订补丁逻辑）  
   - 部分迁出时原行保留，剩余可迁出仍在原供应商下  
5. 成功确认：「已生成新订单 {orderId}，原行对应套数已撤订，是否立即查看？」→ 取消关闭；确定切换到订单列表。

## 9. 测试要点

1. 可迁出 = 0 或状态不符：无行按钮  
2. 已催缺且其它条件满足：仍显示行按钮  
3. 默认套数 = 可迁出；改小后新行/原行撤订段数量正确  
4. 套数 = 0、超上限、非整数：阻断  
5. 全量迁出且无收/换/退：原行 → 已撤订；部分迁出：原行保留  
6. 成功确定 → 订单列表  
7. 工具栏不再出现「更换供应商」
