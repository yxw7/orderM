# 订户查重范围：四级馆藏地机构排序（结果排序暂缓）

**日期**：2026-08-21（2026-08-24 修订结果侧）  
**状态**：结果排序已收窄；机构可配排序后续  
**模块**：订户管理（配置 → 查重范围）、订单行馆藏查重结果  
**关联**：
- `2026-08-20-subscriber-dedup-scope-design.md`
- PRD 5.9.5.4、5.3.5.5、5.3.5.6

---

## 1. 背景与目标

查重范围中的「所属馆排序」曾按已选**分馆**调序并驱动结果面板排序。产品要求本版**结果侧不做可配置排序**，仅保留固定展示默认。

### 1.1 本版目标（结果侧）

1. 查重结果「单件」页签：**单件列表**不做优先序排序，保持过滤后的接口/原数据相对序。
2. **馆藏树**不做按分馆/机构配置的排序。
3. **唯一展示规则**：一级节点中若存在「首都图书馆」，则置顶；其余一级节点保持原相对序；二/三/四级不重排。

### 1.2 非目标（本版）

- 改造馆址管理主数据或页面
- 真实四级馆藏地后端接口（若做配置侧，原型仍用 mock）
- 数据归属页签业务实现
- **馆藏地（四级叶子）排序**
- **查重结果单件列表按优先序排序**
- **馆藏树按订户机构序 / 分馆序排序**（含原三级所属馆锚点上浮）
- **订户「机构排序」配置与 `dedupOrgCodes`**（无消费方，一并暂缓）

---

## 2. 已确认决策

| 项 | 结论 |
|----|------|
| 单件列表排序 | **暂不做**；叶子过滤后保持原相对序 |
| 馆藏树可配排序 | **暂不做**；旁路既有分馆优先序排序 |
| 馆藏树默认 | 有「首都图书馆」一级节点时**写死置顶**；不读订户机构序 |
| 订户机构排序 UI / `dedupOrgCodes` | **本版不做** |
| 所属分馆有序字段 | 仍可多选落库并参与馆藏查重范围合并；排序区文案改为「所属分馆顺序」，**不再宣称影响结果排序** |

---

## 3. 结果面板规则（本版）

### 3.1 馆藏树

1. `buildDisplayHoldingTree`（含「未关联馆藏地」挂载）之后，对一级节点执行 `pinCapitalLibraryFirst`：
   - 名称等于「首都图书馆」的节点移到一级列表首位；
   - 其余一级节点相对顺序不变；
   - 无该节点则不额外重排。
2. **不调用** `sortHoldingTreeByBranchPriority`（及后续机构序排序）。

### 3.2 单件列表

1. 先按四级叶子（或未关联馆藏地）过滤。
2. **不调用** `sortPhysicalItemsByBranchPriority`；保持过滤后相对序。

### 3.3 与查重范围关系

- `branchCodes` / `collectionCodes` 仍仅用于馆藏检索范围。
- `lastDedupBranchCodes` 可继续存档；**本版不参与结果展示排序**。

## 6. 验收要点

1. 查重结果单件页签：左侧树一级若含「首都图书馆」则排第一；其余一级相对序不变。  
2. 单件列表顺序不随 `lastDedupBranchCodes` / 订户分馆序变化。  
3. 不出现按分馆优先序重排后的树/列表行为。  
4. 订户配置排序区标题为「所属分馆顺序」，不再写「影响单件排序」。  
5. 馆藏查重范围合并与订单查重行为不变。
