# 多租户 library 数据隔离 · 备选方案

**日期**：2026-10-21  
**状态**：待评审  
**定位**：与机构修订 / `2026-10-26-subscriber-derived-institution-isolation-design.md`（订户推导机构墙，当前实现方向）**并列备选**；产品/租户最终只落一种主轴，不叠加双墙。**本文仍未采用**。  
**结构**：镜像机构修订（四态 + `subscriber` / 主墙轨 / `tenant`）；主墙由 institution 置换为 **library**。  
**范围**：订单管理系统全模块（采访业务、订户/馆员、设置、货币）  
**前提已确认**：

- 主墙为所在馆对应的 **单一 library**；同 library 内可跨订户共享（library 轨）。
- 订户轨读墙**仍只按关联订户**，不因所在 library 再砍一刀。
- 订户主数据**已有**所属 library；订户轨写归属取该字段。
- 单据落 `libraryId` / `libraryCode`；单号前缀用 **library code**；`institutionId` 可并存（组织溯源），**不作读墙**。

---

## 1. 背景与目标

### 1.1 为何单独成文

机构修订将「按分馆 / library 硬过滤」列为否决项（与「同机构共享」冲突），并坚持机构为主轴。部分场景需要评估更细的隔离粒度：同机构下不同 library 的验收/结算/馆址等互不可见。

本文给出 **library 主轴** 的完整读写模型，便于与机构修订对照选型，**不**表示已取代机构修订。

### 1.2 目标

1. 业务单据持久化 `libraryId` / `libraryCode`，用于归属、审计与单号前缀；可选并存 `institutionId`（非读墙）。
2. **library 轨**上下文**仅**由登录账号所在馆（`branchId` → library）解析；无所在馆则 library 轨不可用。
3. **订户轨**写 library 取所选/相关订户已有 library；读过滤仅关联订户。
4. 查询过滤按菜单作用域分流：订户轨 / library 轨 / 租户轨。
5. 单号前缀用 `libraryCode`；历史已发前缀不改号。
6. 按 S0～S3 统一读写（与机构修订同态；主墙口径改为 library）；未满足前置时按模块提示（见 §7）。
7. 设置类按需展示 library 列；采访业务页面只存不展示 library 字段。

### 1.3 非目标

- 不与机构墙叠加（不做 institution ∩ library 双过滤）。
- 不要求同机构下其它 library 的数据互见。
- 不迁移历史单号前缀。
- 不改造业务中台账号/分馆同步协议（仅消费所在馆）。
- 不在本版拍板「订单与 MARC 映射」「退换撤订原因参数」是否改为 library 级（保持待定）。

## 2. 方案选型

| 方案 | 说明 | 结论 |
|------|------|------|
| **1. 镜像置换** | 以机构修订为模板；`institution` 轨 → `library` 轨；四态与订户轨矩阵照搬 | **采用**（本文） |
| 2. 仅改读墙、单号仍用机构 code | 读墙按 library，前缀仍 `institution_code` | 否决（与「前缀用 library code」前提冲突） |
| 3. 机构 + library 叠加墙 | 双过滤 | 否决（已选并列二选一） |

## 3. 四态与作用域模型

### 3.1 组织模型

```
租户 (tenant)
 └── 机构 (institution)     ← 组织层级；可落库溯源，本方案不作读墙
      └── 馆区 (campus)
           └── 分馆 (library)  ← **library 墙**；单号前缀 library_code；馆员「所在馆」
                └── 馆藏地 (location)
```

| 概念 | 职责 |
|------|------|
| 租户 | 登录域；货币等全局配置 |
| 机构 | 组织上溯；可选落库；**本方案不作业务读墙** |
| 分馆 (library) | 账号所在馆；library 轨读墙与单号前缀；**同 library 内可跨订户** |
| 订户 | 订单等采访模块的读写授权边界；主数据已含所属 library |

### 3.2 账号四态

| 状态 | 所在馆 | 关联订户 | 读/写原则 |
|------|--------|----------|-----------|
| **S0** | 无 | 无 | **不可**查看/写入任何业务数据 |
| **S1** | 有 | 无 | **library 轨**：本 library 查看；订户/馆员/馆址/条码/验收单头/结算可写。**订户轨**：否/否 |
| **S2** | 无 | 有 | **订户轨**：按关联订户查看与写入（**可**批量验收；**不可**逐条收货）。**library 轨**：否/否 |
| **S3** | 有 | 有 | **订户轨**：按关联订户查看与写入。**library 轨**：本 library 查看与写入（可跨订户） |

### 3.3 解析函数

| 函数 | 规则 |
|------|------|
| `resolveHomeLibraryId()` | `branchId` → library；无分馆 → `null`（S0/S2）；**仅服务 library 轨** |
| `getAssociatedSubscriberIds()` / 名称列表 | 当前馆员关联订户；S0/S1 为空 |
| `resolveOrderLibraryId(subscriberId)` | 取该订户已有 library；订户轨新建订单必选单一订户后调用 |

**明确禁止**：

- 用关联订户 library **合集**充当 library 轨读墙 / `resolveHomeLibraryId()` 的 fallback。
- 用订户所属机构合集或所在馆机构作为本方案主墙（主墙只有 library）。

**明确保留**：订户轨写单据的 `libraryId` / `libraryCode` 取**业务所选/相关订户**已有 library（非所在馆、非合集）。

馆员主数据保留 `branchId`。**不以**馆员表缓存的 `institutionId` / `libraryId` 为权限权威；library 轨需要 library 时调用 `resolveHomeLibraryId()`（实现可做登录会话缓存）。

### 3.4 菜单作用域

| scope | 读过滤 | 写前置 |
|-------|--------|--------|
| `subscriber` | 关联订户 | 须 **S2 或 S3** |
| `library` | `resolveHomeLibraryId()` **单一所在馆** | 须有所在馆（**S1 或 S3**） |
| `tenant` | 租户全局 | 按角色；**S0 仍不可进业务数据页**（见 §4.3） |

创建时写入 `libraryId` / `libraryCode`（及可选 `institutionId`）：

- **订户轨**（订单等）：library 取所选订户已有 library；institution 可由订户/library 上溯写入（非读墙）。
- **library 轨**（验收单头、结算等）：library 取创建人所在馆。
- 编辑已有单据不改归属字段。

## 4. 分模块读写矩阵

未满足前置时：规格默认按下列**提示**展示。实现若统一改回静默空态，须在实现计划中显式推翻本节。

### 4.1 `subscriber` 轨

| 页面 | S0 | S1 | S2 | S3 | 数据权限范围 |
|------|----|----|----|----|-------------|
| 订单管理 | 否/否 | 否/否 | 是/是 | 是/是 | 关联订户；新建**必须选单一订户**，写 library = 该订户已有 library |
| 书目查询·订单页签 | 否/否 | 否/否 | 是/是 | 是/是 | 同上；**书目/Z39.50 检索本身**不按本表阻断 |
| 逐条收货 | 否/否 | 否/否 | 否/否 | 是/是 | 可配订单行 = 关联订户；验收单 library 须 = 订单/订户 library（须 S3） |
| 批量验收 | 否/否 | 否/否 | 是/是 | 是/是 | 可配订单行 = 关联订户；验收单 library 须 = 订单/订户 library（**不**要求操作人所在馆；S2 可用） |
| 换货 / 退货 / 催缺 | 否/否 | 否/否 | 是/是 | 是/是 | 关联订户；写 library 取相关订户已有 library |
| 催缺配置 | 否/否 | 否/否 | 是/是 | 是/是 | 关联订户 |
| 订单导入模板（配置页与业务选用） | 见下 | 见下 | 见下 | 见下 | 见下 |

**订单导入模板可见性（配置页列表与业务选用同一规则）**：

- 模板**未**关联任何订户 → 租户内所有账号可见（仍受角色是否可进配置页约束；**S0 除外**）。
- 模板**已**关联一个或多个订户 → 仅当馆员关联订户与模板关联订户**有交集**时可见/可选。
- S0 → 不可见任何业务配置/选用。
- S1（无关联订户）→ 只能看见「未关联订户」的模板；写配置仍按角色。
- 本方案焦点是可见性；不把模板改成 library 轨。

提示：S0/S1 →「当前账号未关联订户」。

### 4.2 `library` 轨

| 页面 | S0 | S1 | S2 | S3 | 数据权限范围 |
|------|----|----|----|----|-------------|
| 验收单管理 | 否/否 | 是/是 | 否/否 | 是/是 | 所在馆→单一 library；**同 library 可跨订户**；新建写 library |
| 待结算 / 已结算 / 结算失败 | 否/否 | 是/是 | 否/否 | 是/是 | **与验收单同口径**（结算按验收单） |
| 订户列表 | 否/否 | 是/是 | 否/否 | 是/是 | **S1**：本 library 全部订户；**S3**：仅本人关联订户 |
| 馆员列表 | 否/否 | 是/是 | 否/否 | 是/是 | **S1**：本 library 全部馆员；**可**「订户关联馆员」，候选订户 = 本 library 全部订户。**S3**：仅与本人关联订户相关的馆员行；关联操作仅能使用本人已关联订户 |
| 馆址管理 | 否/否 | 是/是 | 否/否 | 是/是 | 本 library |
| 条码号供应商 / 条码校验规则 | 否/否 | 是/是 | 否/否 | 是/是 | 本 library |

提示：S0/S2 →「当前账号无所在馆」。

### 4.3 `tenant` 轨

| 页面 | S0 | S1～S3 | 范围 |
|------|----|--------|------|
| 货币信息 | 否/否 | 是/是（按角色） | 租户全局 |
| 订单与 MARC 类型映射 | 否/否 | 暂按租户全局 | **待定**是否改 library 级 |
| 退换撤订原因参数 | 否/否 | 暂按租户全局 | **待定**是否改 library 级 |

### 4.4 验收域内部分工

- **S1**：可维护验收单头/列表与结算（library 口径）；**不可**逐条收货、批量验收。
- **S2**：不可维护验收单头/结算（library 轨列表不可用）；**不可**逐条收货；**可**批量验收（凭已有验收单进入）：按关联订户匹配订单行，且 `acceptance.libraryId === (订单.libraryId ?? 订户.libraryId)`。
- **S3**：验收单/结算（本 library，可跨订户）+ 逐条收货/批量验收（订户 ∩ 该验收单 library）。
- 验收单头不设订户字段；匹配订单行时校验订户关联且 library 一致（优先订单已落库 `libraryId`，否则订户已有 `libraryId`）。

## 5. 落库、单号与历史

### 5.1 落库

| 实体 | library 字段 | 赋值 | institution（可选） |
|------|--------------|------|---------------------|
| 订单 / 订单行 | `libraryId`, `libraryCode` | 创建时取**所选订户**已有 library（订单行继承订单）；S2/S3 同一规则 | 可由订户/library 上溯 |
| 验收单 | 同上 | 创建人当时所在馆（须 S1/S3）；无订户头字段 | 可由所在馆上溯 |
| 催缺 / 换货 / 退货 | 同上 | 取相关订户已有 library（订户轨；S2/S3） | 可选上溯 |
| 结算批次等 | 同上 | 操作人所在馆（library 轨；须 S1/S3） | 可选上溯 |

采访业务 UI 不展示 library / 机构列（只存）。

### 5.2 单号

前缀为 `libraryCode`；流水键 `tenant + libraryCode + docType + date`；历史已发单号不改号。

### 5.3 历史补齐

存量缺 `libraryId`：按订户已有 library、或创建人所在馆、或实现计划约定的映射补写。补齐后 library 轨过滤使用单据上的 `libraryId`。具体迁移步骤在选定本方案后的实现计划中展开。

## 8. 共享实现要点（前端 Mock / 后续后端）

建议集中于 `current-librarian.js`（或 `library-context.js`）：

| API | 职责 |
|-----|------|
| `getAccountReadiness()` | `s0`～`s3` |

验收匹配订单行伪码（逐条收货仅 S3；批量验收 S2/S3）：

```
可匹配 ⇔ 订单.subscriber ∈ 关联订户
      AND (订单.libraryId ?? 订户.libraryId) === acceptance.libraryId
      AND 头信息维度一致
```

## 9. 测试要点

1. S0：任意业务页无数据、不可写。  
2. S2：订单/催缺/批量验收等按关联订户可读写；**不可**逐条收货；新建订单必选订户且 library = 该订户 library；验收/馆址/结算进入提示无所在馆。  
3. S1：本 library 订户/馆员/馆址/条码/验收单头/结算可用；不能收货、不能建订单；可为馆员关联本 library 订户。  
4. S3：订单按关联订户；验收/结算仅本 library；同机构**另一 library** 账号**不能**看见本 library 验收单（相对机构修订的关键差异）。  
5. S3 关联订户属其它 library 时：仍**不能**在 library 轨看见该其它 library 的验收/结算。  
6. 导入模板绑定订户 A 后，未关联 A 的馆员不可见该模板。  
7. 历史单号不改；补 `libraryId` 后 library 过滤生效。
