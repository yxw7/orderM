# 催缺撤订 / 更换供应商 — 订单行状态联动设计

**日期**：2026-07-28  
**状态**：已评审待实现  
**模块**：采访验收 / 催缺管理、催缺详情；非连续出版物订单  
**关联**：催缺详情页（列表点催缺单号进入）；现有 `cancelOrders`、`flowStats`（发/收/换/退/撤订）

---

## 1. 背景与目标

催缺管理列表的「撤订」「更换供应商」，以及催缺详情对订单行的「撤订」，需按套数联动更新原订单行状态，并在更换供应商时生成新订单与新订单行。当前实现仅更新催缺单备注/状态，未回写订单行。

### 1.1 目标

- 统一公式：**撤订套数 = max(催缺套数 − 到货套数, 0)**
- 按行比较撤订套数与发订套数，更新 `flowStats`、行状态、验收状态
- 更换供应商：先按上式撤订原行，再按撤订套数生成新订单 + 新订单行
- 列表整单、详情按行共用同一套规则函数

### 1.2 非目标

- 改造订单模块原有「撤订」入口的全量撤订语义（订单列表/订单行列表仍走现有 `cancelOrders`）
- 后端接口；本期为前端原型 store 联动
- 催缺详情「更换供应商」（本期仅列表提供）

---

## 2. 方案

**共享领域函数 + store 编排（已选）**

| 层 | 职责 |
|----|------|
| `shortage-actions.js` | `calcCancelSets`、按 flowStats 重算行状态、整单/按行撤订补丁、更换供应商产出（原行补丁 + 新单/新行） |
| `shortage` store | 解析催缺单内订单行、调用 actions、更新催缺单状态与详情行 |
| `order` store | 应用订单行补丁；创建新订单与新订单行 |

---

## 3. 核心规则

### 3.1 撤订套数

```
撤订套数 = max(催缺套数 − 到货套数, 0)
```

- 列表整单：对催缺单内**每个**可操作订单行分别计算
- 详情：对所选订单行分别计算
- 详情若展示册数：`套数 = floor(册数 / 套内册数)`，`copiesInSet` 缺省为 1；实现时详情行补齐 `shortageSets` / `arrivedSets`（或由册数字段换算），保证公式可算

撤订套数为 0 的行：跳过，不改订单行。

### 3.2 发订套数

取订单行 `flowStats` 发订段；若缺失则用行上 `sets`。

### 3.3 订单行更新（撤订与更换供应商共用）

1. `flowStats` 撤订段累加本次撤订套数（发/收/换/退段不变）
2. 比较本次撤订套数与发订套数：
   - **撤订套数 = 发订套数** → `lineStatus = 已撤订`，`acceptanceStatus = ''`
   - **撤订套数 < 发订套数** → 按更新后 flowStats 重算：
     - 有效待收 = 发订 − 撤订（更新后撤订段）
     - 到货（收货段）= 0 → 验收「待验收」，行状态「已发订」
     - 0 < 到货 < 有效待收 → 验收「部分收货」，行状态「处理中」
     - 到货 ≥ 有效待收 → 验收「收货完成」，行状态「已关闭」
3. 备注追加撤订原因（`hasRemark = true`）

### 3.4 催缺单状态

- 列表整单撤订 / 更换供应商完成后：该催缺单 `status = done`，`actions = false`，备注记录原因或更换说明
- 详情按行撤订：对应详情行 `status = done`，不可再撤订；若该单全部可操作行均已完成，催缺单同步 `done`

## 4. 交互

### 4.1 催缺管理列表

| 操作 | 行为 |
|------|------|
| 撤订 | 弹窗选原因 → 对所选催缺单内全部可操作订单行执行 §3 → 催缺单标已完成 → 提示「撤订成功」 |
| 更换供应商 | 弹窗选供应商/预算/备注 → 先 §3 整单撤订 → 再 §5 建新单 → 催缺单标已完成 → 提示含新订单号 |

作用范围：**整张催缺单**（勾选多张则逐张处理）。

### 4.2 催缺详情

| 操作 | 行为 |
|------|------|
| 单行撤订 / 批量撤订 | 仅处理所选订单行 → §3 → 更新详情行与催缺单状态 |

订单行号仍跳转订单行详情，便于核对。

---

## 5. 更换供应商 · 新单生成

在完成原行撤订后：

1. **新订单**：供应商、预算取弹窗；备注取弹窗；状态「待发订」；馆址、资源类型、语种等从原订单继承；生成新订单号（对齐现有新建订单号规则）
2. **新订单行**（每个撤订套数 > 0 的原行一条）：
   - 复制书目与资源字段（题名、资源标识、作者、出版社、定价、币种、套内册数等）
   - `sets` = 该行撤订套数
   - `lineStatus = 待发订`，`acceptanceStatus = ''`
   - `flowStats` 与现有待发订行一致（如 `sets/0/0/0/0` 或项目内待发订惯例）
   - `isShortage = 否`
3. 原订单行保留，不删除

## 8. 验收要点

- 列表撤订后：对应订单行 `flowStats` 撤订段增加；全量撤订行变为已撤订且验收为空；部分撤订行按 §3.3 重算
- 详情撤订仅影响所选行；全部行撤订完后催缺单不可再操作
- 更换供应商：原行已按撤订更新；存在新待发订订单及套数正确的新订单行
- 撤订套数为 0 的行不被改写
