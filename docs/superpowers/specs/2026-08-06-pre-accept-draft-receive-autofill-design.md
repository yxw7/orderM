## 1. 背景与目标

书商发货单格式不一，需先预验收核对差异并保存通过数据；真正收货仍在逐条收货中由馆员校对确认。若「凡已映射字段都必须与订单行一致才成功」，则成功行草稿几乎等于订单行原值，导入带入意义弱。故改为：**由用户勾选「须一致」字段**；未勾选字段允许与订单行不同，仍可成功并写入草稿供收货窗带入。

### 1.1 目标

- 验收单管理**仅保留预验收**；移除批验收入口
- 四步向导：上传 → 字段映射（含表头行号 / 模板 / 须一致）→ 数据解析 → 数据入库
- 表头行为 Excel **物理行号**输入（**无**原始文件预览）
- 系统标准字段按验收单 **资源类型 × 语种（中文/外文）** 四套展示
- 校验：套数 `0 ＜ 收货套数 ≤ 待收` 通过；**仅勾选「须一致」的已映射字段**与订单行不等 → 不一致失败
- **允许部分成功**：通过行写入预验收草稿（覆盖同订单行**已有草稿**，不改订单行本身）
- 失败行单独下载：原发货单列 + 失败原因
- 逐条收货打开收货窗时带入草稿对应字段；确认收货后清除草稿

### 1.2 非目标

- 供应商固定模板包
- 自动猜测表头行
- 原始文件预览 / 点选表头行
- 批验收 / 导入即收货
- 异步导入任务
- 改造侧栏「批量验收」页
- 换货/退货页带入预验收

## 2. 方案

**改造现有预验收向导 + 验收单维度草稿存储**。

2026-08-07 修订要点：
- 向导：上传 → 字段映射 → 数据解析 → **数据入库**（第 3 步「下一步」写入草稿并展示入库结果）
- 去掉原始文件预览
- 不一致校验改为用户自定义「须一致」/「是否校验」字段（映射表旁勾选，按标准字段 key 去重）

## 3. 入口

| 条件 | 结果 |
|------|------|
| 已关联订户 + 勾选恰好 1 条未开始/进行中验收单 | 可打开预验收；打开前设为当前工作验收单 |

## 4. 向导步骤

```text
① 上传文件 → ② 字段映射 → ③ 数据解析 → ④ 数据入库
```

### 4.1 上传

仅 `.xls` / `.xlsx`。通过后进入②。

### 4.2 字段映射

同一屏配置：

1. **映射模板**：选择 / 保存 / 删除（保存与更新合并为「保存模板」）。  
2. **表头行号**：Excel **物理行号**（从 1 起，必填）+「**读取表头**」按钮触发生成列名；无原始预览。修改行号后须再点读取，否则不可进入③。从①进入②时**不**自动读取。  
3. **列映射表**三列：

| 文件列名 | 系统标准字段 | 须一致 |
|---------|-------------|--------|

规则：
- 文件列 → 系统标准字段（扁平下拉）；字段池见 §5  
- 「不映射」时「须一致」清空并禁用  
- **订单行号**、**收货套数**不提供「须一致」勾选（行号用于匹配；套数走 §6.1）  
- 默认勾选「是否校验」：**实洋、套内册数/件数、定价（纸质）/码洋（视听）**；其余默认不勾  
- 同一标准字段被多列映射时：任一列勾选即计入该字段须一致（按标准字段 key 去重）  
- 表头行号无效（未读取或已变更未再读）不可进入③；必填字段是否已映射仅在点击「下一步」时校验，未齐则提示并停留本步（不实时禁用下一步）

### 4.3 数据解析

校验进度 → 成功/失败汇总。提示：点击「下一步」只导入成功行。全部失败时「下一步」不可用。失败可下载。

### 4.4 数据入库

第 3 步「下一步」进入本步并写入通过行草稿。面板结果：

- 成功：绿色圆标 ✓ +「入库成功」（样式对齐订单导入向导）
- 失败：红色圆标 × +「入库失败，请联系管理员」

然后「关闭」退出向导。入库过程中不可关闭。

**模板内容**：`headerRow` + `columnMapping` + `mustMatchFields: string[]`（标准字段 key）。应用模板时三者一并恢复。

## 5. 系统标准字段（四套）

语种：验收单语种为「中文」走中文池；其余语种一律走外文池。

### 5.1 纸质书 · 中文

**必填\***：订单行号、收货套数、套内册数、实洋、定价  

**可选**：正题名、ISBN、副题名、分卷号、分卷名、分类号、出版社、作者、出版年、版本、丛编、主题词、读者对象、装帧形式、尺寸、正文语种、卷数、出版地、一般性附注、图书简介、备注  

### 5.2 纸质书 · 外文

**必填\***：订单行号、收货套数、套内册数、实洋、定价  

**可选**：ISBN、学科大类、学科细分、中图分类号、中译名、题名、副题名、责任者、丛编、出版社、装帧形式、出版日期、版次、页数、币种、主题词、读者对象、尺寸、语种、简介、精简装ISBN对照、馆藏信息、审读级别、获奖信息、目次信息、分卷号、分卷名、作者简介、书评、备注  

### 5.3 视听资料 · 中文

**必填\***：订单行号、收货套数、套内件数、实洋、码洋  

**可选**：ISBN、ISRC、题名、载体、出版社、版本/格式、著者、币种、彩胶颜色、限量编号、厂牌、系列名称、是否签名、是否老唱片、获奖信息、北京出版社、分类、盘号、老唱片品牌、剧种、年代、备注  

### 5.4 视听资料 · 外文

**必填\***：订单行号、收货套数、套内件数、实洋、码洋

## 6. 校验规则

匹配池：关联订户下可收货订单行，且与验收单 **资源类型、语种（中/外分档）、采选方式、供应商** 一致。

### 6.1 套数

| 条件 | 结果 |
|------|------|
| 无法解析 / 空 | 数据错误 |
| ≤ 0 | 套数非法（`套数 ≤ 0`） |
| ＞ 待收 | 套数非法（`套数大于待收`） |
| **0 ＜ 套数 ≤ 待收** | **该维度通过** |

### 6.2 须一致字段（用户勾选）

- 仅对 `mustMatchFields` 中、且当前已映射的标准字段，与订单行比对；不等 → **不一致**  
- **未勾选**的已映射字段：不做不一致失败；发货单值可写入草稿  
- 金额两位小数；数量按数值  
- 订单行号、收货套数不参与本条（见 §4.2 / §6.1）

### 6.3 其它类型

数据错误、未匹配、验收单不匹配 — 含义同既有逻辑。同行多种失败类型用 `；` 拼接。页面汇总：有任一失败类型计失败。

### 6.4 下载失败数据

仅失败行。列：**原发货单全部列（原顺序）+ 失败原因**（不含「校验结果」列）。Excel（.xls）。

## 7. 预验收草稿

| 项 | 约定 |
|----|------|
| 维度 | 验收单号 + 订单行号 |
| 内容 | 通过行的发货单已映射值（含未勾选「须一致」的差异字段，供收货窗带入） |
| 写入 | 第 4 步「数据入库」时仅写入通过行；同订单行再次预验收 → **覆盖已有草稿**（不改订单行） |
| 清除 | 该订单行在逐条收货中**确认收货成功**后删除草稿 |
| 实现 | 前端 mock：localStorage；键含验收单号 |

全部失败时不写草稿且第 3 步「下一步」不可用。预验收导入不改变验收单状态。

## 8. 逐条收货带入

打开收货窗 / 合并处置面板「收货」页签时，若当前工作验收单下该订单行存在草稿，则预填：

| 收货窗控件 | 纸质书 | 视听资料 |
|------------|--------|----------|
| 收货套数 | 草稿收货套数 | 同左 |
| 定价 / 码洋 | 定价 | 码洋 |
| 实洋 | 实洋 | 实洋 |
| 套内册数 / 件数 | 套内册数 | 套内件数 |

无草稿则保持现有默认。用户可改后确认；确认收货成功 → 清除该行草稿。换货/退货不带入。

处置窗收货区标题旁展示「已带入预验收数据」（仅当该订单行存在草稿时）。

列表「预验收」标记：建议 P1，非本期必做。

## 10. 测试要点

1. 无批验收入口；预验收勾选与订户前置正确  
2. 四步向导；第 2 步无原始预览；表头行号输入生效；模板恢复表头 + 映射 + 须一致  
3. 订单行号/收货套数无「须一致」；其它字段勾选后不一致才失败；未勾选差异仍可成功并进草稿  
4. `0 ＜ 套数 ≤ 待收` 不因套数失败；部分成功写入草稿；全部失败第 3 步下一步置灰  
5. 第 4 步入库成功/失败面板提示正确  
6. 失败下载仅失败行：原列 + 失败原因  
7. 逐条收货带入对应字段（含发货单差异金额/册数）；确认收货后草稿清除；再预验收同单行覆盖已有草稿
