## 1. 背景与目标

一张书商发货单常含多个订单号的订单行。验收单管理下的验收单可跨订单号验收并可分配条码。批验收在映射与可收货性校验通过后，将发货单数据批量写入所选验收单。

### 1.1 目标

1. 上传文件  
2. 字段映射（五字段必填 + 可选书目字段）  
3. 解析文件（匹配 + 套数合法；不比对一致性）
4. 确认验收（用发货单数据收货；可选条码）

### 1.2 非目标

- 异步导入任务  
- 批验收换货、退货  
- 侧栏「批量验收」模型改造  
- 字段一致性拦截（改由预验收承担）

---

## 2. 入口与前置

| 条件 | 结果 |
|------|------|
| 勾选恰好 1 条，状态未开始或进行中 | 「批验收」可点 |
| 0 / 多条 / 已结束 | 置灰 |
| 未关联订户 | 提示无操作权限 |

---

## 3. 字段映射

与预验收相同：

- 必填：订单行号、码洋、实洋、收货套数、套内册数  
- 可选：纸质书 / 视听合并字段池  
- 模板 profile：`批验收`  
- 不做「表头必须等于固定模板」阻断；以映射是否完整为准  

---

## 4. 向导步骤

```text
① 上传文件 → ② 字段映射 → ③ 解析文件 → ④ 确认验收
```

### 4.1 上传

仅 xls/xlsx；取消 / 上传。

### 4.2 字段映射

见 §3；取消 / 下一步。

### 4.3 解析文件

1. 订单行号在关联订户 + 验收单上下文可收货池中查找  
2. 套数 ≤0 或 ＞待收 → **套数非法**  
3. `0 < 套数 ≤ 待收` 且已命中 → **通过**（**不**比对码洋/实洋/书目等）  
4. 多失败类型时结果/原因分号拼接（批验收通常单一类型）  
5. 汇总「共校验到 X 条，其中 X 条成功，X 条失败。」；提示全部成功才可收货  
6. 下载：原导入列 + 校验结果 + 失败原因  
7. 存在失败行 → **不可进入确认验收**

| 校验结果 | 条件 | 失败原因示例 |
|--------|------|-------------|
| 通过 | 命中且 0＜套数≤待收 | — |
| 未匹配 | 无对应可收货订单行 | 无对应可收货订单行 |
| 套数非法 | ≤0 或 ＞待收 | `套数 ≤ 0` / `套数大于待收` |
| 数据错误 | 解析失败等 | 数据解析失败 |

### 4.4 确认验收

- 汇总：总种数 / 总套数 / 总册数 / 总码洋 / 总实洋（按发货单值）  
- 确认：验收单须仍为未开始/进行中  
- 逐行：发货套数 ≤ **实时**待收 → 用发货单已映射值写入；超出 → 该行失败  
- 允许部分成功；`已成功验收 X 条数据，失败 X 条数据。`；失败可下载异常数据；成功行展示条码  
- 有成功行：未开始 → 进行中  

---

## 5. 与预验收对比

| 维度 | 预验收 | 批验收 |
|------|--------|--------|
| 一致性比对 | 是 | 否 |
| 0＜套数＜待收 | 不一致 | 通过 |
| 收货 | 否 | 是（发货单数据） |

---

## 6. 测试要点

1. 按钮文案为「批验收」；未勾选/多选/已结束不可用  
2. 映射缺必填不可下一步  
3. 码洋/题名与订单不一致仍可通过校验（已命中且套数合法）  
4. 套数＞待收 → 套数非法，不可确认  
5. 全通过后确认：写入发货单数量与金额；部分实时待收不足允许部分成功  
6. 导出含原列 + 校验结果 + 失败原因  
7. 未关联订户提示无操作权限
