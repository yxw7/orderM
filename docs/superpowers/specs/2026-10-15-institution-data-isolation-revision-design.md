# 多租户机构数据隔离 · 修订

**日期**：2026-10-15  
**状态**：待评审  
**取代**：`2026-09-21-institution-data-isolation-design.md`（下称「09-21」）  
**关联修正**：`2026-09-24-librarian-home-branch-institution-cache-design.md`（馆员**不**以缓存 `institutionId` 为权限权威；见 §3.1）  
**范围**：订单管理系统全模块（采访业务、订户/馆员、设置、货币）  
**前提已确认**：同机构内数据共享，按订户授权；**不要求**同机构下分馆互不可见。

---

## 1. 背景与目标

### 1.1 为何修订

09-21 以「所在分馆倒推机构 + 订户 fallback」与「验收按订户机构合集」为主。评审后确认：

- 租户内多机构需要**机构墙**；同机构内应按**订户**授权，而非按分馆切开业务数据。
- 写机构快照必须有可靠的所在馆；**无分馆（S2）不应再靠订户 fallback 写入 / 可写业务**。
- 验收与结算同属验收域，读范围应一致，且机构范围定为所在馆倒推的**单一机构**（不再用订户机构合集）。
- 菜单级作用域需显式分为 `subscriber` / `institution` / `tenant`，避免「有的按合集、有的按订户」难以实现。

曾讨论「按所在馆做业务硬过滤」方案；因「同机构共享」被否决，本修订**坚持机构为主轴**。

### 1.2 目标

1. 业务单据持久化 `institutionId` / `institutionCode`，用于归属、审计与单号前缀。
2. 机构上下文**仅**由登录账号所在分馆倒推；无分馆则无机构上下文（不可写机构敏感数据）。
3. 查询过滤按菜单作用域分流：订户轨 / 机构轨（单一所在馆机构）/ 租户轨。
4. 单号前缀仍用机构 `institution_code`；历史前缀不改号。
5. 按 S0～S3 统一读写；未满足前置时按模块提示（见 §7）。
6. 设置类按需展示机构列；采访业务页面只存不展示机构字段。

### 1.3 非目标

- 不以分馆 / `library_code` 做采访业务列表硬隔离。
- 不迁移历史单号前缀。
- 不改造业务中台账号/分馆同步协议（仅消费所在馆）。
- 不在本版拍板「订单与 MARC 映射」「退换撤订原因参数」是否改为机构级（保持待定）。

## 3. 四态与作用域模型

### 3.1 组织模型

```
租户 (tenant)
 └── 机构 (institution)     ← 机构墙；单号前缀 institution_code
      └── 馆区 (campus)
           └── 分馆 (branch)  ← 馆员「所在馆」（中台 branchId）
                └── 馆址 (site)
                     └── 馆藏地 (collection)
```

| 概念 | 职责 |
|------|------|
| 租户 | 登录域；货币等全局配置 |
| 机构 | 验收/结算/馆址/条码等归属与读墙；单据机构快照；单号前缀 |
| 分馆 | 账号所在馆；**唯一**倒推机构的路径；**不做**业务列表硬过滤 |
| 订户 | 订单等采访模块的读写授权边界 |

### 3.2 账号四态

| 状态 | 所在馆 | 关联订户 | 含义 |
|------|--------|----------|------|
| **S0** | 无 | 无 | 未就绪 |
| **S1** | 有 | 无 | 机构侧维护（订户/馆员/馆址/条码/验收单头/结算等） |
| **S2** | 无 | 有 | 订户轨**只读**；机构轨不可用（无法解析机构） |
| **S3** | 有 | 有 | 采访业务完全就绪 |

### 3.3 解析函数

| 函数 | 规则 |
|------|------|
| `resolveHomeInstitutionId()` | `branchId` → 机构；无分馆 → `null`（S0/S2） |
| `getAssociatedSubscriberIds()` / 名称列表 | 当前馆员关联订户；S0/S1 为空 |

**废除（相对 09-21）**：

- 用关联订户 fallback 解析/写入机构上下文。
- `resolveLibrarianInstitutionIds()` / `resolveInstitutionScopeIds()` 在 S2/S3 返回「订户机构合集」作为验收/馆址/条码读墙（本修订机构轨一律用所在馆单一机构）。

馆员主数据保留 `branchId`。**不以**馆员表缓存的 `institutionId` 为权限权威；需要机构时调用 `resolveHomeInstitutionId()`（实现可做登录会话缓存）。09-24 若已落库机构字段，仅可作展示优化，须与实时解析一致，冲突时以分馆→机构为准。

### 3.4 菜单作用域

| scope | 读过滤 | 写前置 |
|-------|--------|--------|
| `subscriber` | 关联订户 | 须 **S3**（S2 只读） |
| `institution` | `resolveHomeInstitutionId()` **单一机构** | 须有所在馆（**S1 或 S3**） |
| `tenant` | 租户全局 | 按角色（不按四态空库） |

创建业务单据时写入当时的 `institutionId` / `institutionCode`（来自所在馆）。编辑已有单据不改机构字段。

## 4. 分模块读写矩阵

未满足前置时：规格默认按下列**提示**展示（相对 09-21「空白不提示」的变更）。实现若统一改回静默空态，须在实现计划中显式推翻本节。

### 4.1 `subscriber` 轨

| 页面 | S0 | S1 | S2 | S3 | 数据权限范围 |
|------|----|----|----|----|-------------|
| 订单管理 | 否/否 | 否/否 | 是/否 | 是/是 | 关联订户；S3 新建写机构 |
| 书目查询·订单页签 | 否/否 | 否/否 | 是/否 | 是/是 | 同上；**书目/Z39.50 检索本身**不按本表阻断 |
| 逐条收货 / 批量验收 | 否/否 | 否/否 | 是/否 | 是/是 | 当前验收单须属本机构；可配订单行 = 关联订户且订单/订户机构 = 验收单机构 |
| 换货 / 退货 / 催缺 | 否/否 | 否/否 | 是/否 | 是/是 | 关联订户 |
| 催缺配置 | 否/否 | 否/否 | 是/否 | 是/是 | 关联订户 |
| 订单导入模板（配置页与业务选用） | 见下 | 见下 | 见下 | 见下 | 见下 |

**订单导入模板可见性（配置页列表与业务选用同一规则）**：

- 模板**未**关联任何订户 → 租户内所有账号可见（仍受角色是否可进配置页约束）。
- 模板**已**关联一个或多个订户 → 仅当馆员关联订户与模板关联订户**有交集**时可见/可选。
- S0/S1（无关联订户）→ 只能看见「未关联订户」的模板；写配置仍按角色。
- 本修订焦点是可见性；不把模板改成机构轨。

提示：S0/S1 →「当前账号未关联订户」；S2 →「当前账号无所在馆」（只读）。

### 4.2 `institution` 轨

| 页面 | S0 | S1 | S2 | S3 | 数据权限范围 |
|------|----|----|----|----|-------------|
| 验收单管理 | 否/否 | 是/是 | 否/否 | 是/是 | 所在馆→单一机构；**同机构可跨订户**；新建写机构 |
| 待结算 / 已结算 / 结算失败 | 否/否 | 是/是 | 否/否 | 是/是 | **与验收单同口径**（结算按验收单） |
| 订户列表 | 否/否 | 是/是 | 否/否 | 是/是 | **S1**：本机构全部订户；**S3**：仅本人关联订户 |
| 馆员列表 | 否/否 | 是/是 | 否/否 | 是/是 | **S1**：本机构全部馆员；**可**「订户关联馆员」，候选订户 = 本机构全部订户。**S3**：仅与本人关联订户相关的馆员行；关联操作仅能使用本人已关联订户 |
| 馆址管理 | 否/否 | 是/是 | 否/否 | 是/是 | 本机构 |
| 条码号供应商 / 条码校验规则 | 否/否 | 是/是 | 否/否 | 是/是 | 本机构 |

提示：S0/S2 →「当前账号无所在馆」。

### 4.3 `tenant` 轨

| 页面 | S0～S3 | 范围 |
|------|--------|------|
| 货币信息 | 是/是（按角色） | 租户全局 |
| 订单与 MARC 类型映射 | 暂按租户全局 | **待定**是否改机构级 |
| 退换撤订原因参数 | 暂按租户全局 | **待定**是否改机构级 |

### 4.4 验收域内部分工

- **S1**：可维护验收单头/列表与结算（机构口径）；**不可**逐条收货、批量验收。
- **S3**：验收单（机构）+ 收货（订户 ∩ 该验收单机构）。
- 验收单头不设订户字段；匹配订单行时校验订户关联且机构一致（优先订单已落库 `institutionId`，否则订户 `institutionId`）。

## 5. 落库、单号与历史

### 5.1 落库

| 实体 | 机构字段 | 赋值 |
|------|----------|------|
| 订单 / 订单行 | `institutionId`, `institutionCode` | 创建时（订单行继承订单） |
| 验收单 | 同上 | 创建人当时所在馆机构；无订户头字段 |
| 催缺 / 换货 / 退货 / 结算批次等 | 同上 | 创建/操作人所在馆机构 |

采访业务 UI 不展示机构列（只存）。

### 5.2 单号

与 09-21 相同：前缀为 `institutionCode`；流水键 `tenant + institutionCode + docType + date`；历史 `PG001…` 不改号。

### 5.3 历史补齐

存量缺 `institutionId`：单号前缀映射、或明细/订户机构补写（沿用 09-21 迁移思路）。补齐后机构轨过滤使用单据上的 `institutionId`。

## 8. 共享实现要点（前端 Mock / 后续后端）

建议集中于 `current-librarian.js`（或 `institution-context.js`）：

| API | 职责 |
|-----|------|
| `getAccountReadiness()` | `s0`～`s3` |
| `resolveHomeInstitutionId()` | 所在馆→机构 |
| `assertSubscriberReadable()` / `assertSubscriberWritable()` | 订户轨；写仅 S3 |
| `assertInstitutionReadable()` / `assertInstitutionWritable()` | 机构轨；须有所在馆 |
| `filterByHomeInstitution(rows)` | `row.institutionId === homeId` |
| `filterByAssociatedSubscribers(rows)` | 既有订户过滤 |
| `filterImportTemplatesForLibrarian` | **恢复/改为**按关联订户可见性（与 09-21「移除过滤」相反） |

验收匹配订单行伪码：

```
可匹配 ⇔ 订单.subscriber ∈ 关联订户
      AND (订单.institutionId ?? 订户.institutionId) === acceptance.institutionId
      AND 头信息维度一致
```

## 9. 测试要点

1. S2：订单列表可见、新建不可用；验收/馆址/结算进入提示无所在馆。  
2. S1：本机构订户/馆员/馆址/条码/验收单头/结算可用；不能收货、不能建订单；可为馆员关联本机构订户。  
3. S3：订单按关联订户；验收/结算仅本机构；同机构另一分馆账号能看见同一机构验收单。  
4. S3 关联订户属其它机构时：仍**不能**看见该其它机构验收/结算（单一所在馆机构墙）。  
5. 导入模板绑定订户 A 后，未关联 A 的馆员不可见该模板。  
6. 历史单号不改；补 `institutionId` 后机构过滤生效。
