# 预验收与批验收 — 映射校验对齐设计

**日期**：2026-07-27  
**状态**：已评审待实现  
**模块**：采访验收 / 验收单管理  
**关联**：
- 取代并 supersede：`2026-07-22-batch-pre-accept-import-wizard-design.md` 中与本期冲突的约定（固定模板、四字段一致性拦截、三步无映射等）
- 更新：`2026-07-27-pre-accept-wizard-design.md`（套数分类、多结果并列、导出列）
- 入口文案：「导入发货单」→ **「批验收」**

---

## 1. 背景与目标

预验收与批验收并列入口。预验收负责核对差异（含字段一致性）；批验收在映射后只做可收货性校验，**通过行一律用发货单数据验收**，不再因书目/金额不一致阻断收货。

### 1.1 目标

- 两边共用上传 + 字段映射交互（五字段必填 + 纸质书/视听合并可选字段）
- 校验按模式分叉：`precheck`（预验收）/ `receive`（批验收）
- 下载校验结果 = **原导入文件列 + 校验结果 + 失败原因**
- 同一行可并存多种失败类型（结果列与原因列均分号拼接）

### 1.2 非目标

- 数据预览步
- 异步导入任务
- 改造侧栏「批量验收」页

---

## 2. 方案

**共享映射组件 + 分叉校验**（已选）：

- `PreAcceptWizardModal`：3 步  
- `BatchImportWizardModal`：4 步（标题与按钮文案为「批验收」）  
- 共用：字段池、映射模板能力、`validateRow(mode)`、`exportValidationCsv`、套数分类辅助  

映射模板 profile 分离：`预验收` / `批验收`，避免互相覆盖。

---

## 3. 入口

| 按钮 | 前置 |
|------|------|
| 预验收 | 须有关联订户；**不**勾选验收单 |
| 批验收 | 须有关联订户；勾选恰好 1 条未开始/进行中验收单 |

未关联订户提示：`您没有关联订户，无操作权限`。

---

## 4. 向导步骤

### 4.1 预验收

```text
① 上传 → ② 字段映射 → ③ 数据校验 → 完成
```

### 4.2 批验收

```text
① 上传 → ② 字段映射 → ③ 数据校验 → ④ 确认验收
```

第 ③ 步须 **全部行通过** 才可进入第 ④ 步。

### 4.3 字段映射（两边相同）

必填：订单行号、码洋、实洋、收货套数、套内册数。  
可选：纸质书合并池 / 视听合并池（见预验收规格字段清单）。  
下拉分组：通用（必填）/ 纸质书 / 视听资料。

---

## 5. 校验规则

### 5.1 共用收集逻辑

对每一行 **尽量收集全部适用问题**（不因某一失败类型提前结束整行，下列除外）：

- **数据错误**：无法解析必填值等 → 通常仅此类型（后续比对无意义）  
- **未匹配**：无订单行 → 仅此类型（无法比对字段/套数与系统行）  
- 已命中后：可同时产生 **套数非法** 与 **不一致**（预验收）

**校验结果** 列：多种类型用 `；` 连接，如 `套数非法；不一致`。  
**失败原因** 列：对应原因同样 `；` 连接。  
页面汇总：有任一失败类型的行计为失败；无失败类型为成功。

### 5.2 套数

| 条件 | 预验收 (`precheck`) | 批验收 (`receive`) |
|------|---------------------|---------------------|
| 套数 ≤ 0 | 套数非法（`套数 ≤ 0`） | 套数非法（`套数 ≤ 0`） |
| 套数 ＞ 待收 | 套数非法（`套数大于待收`） | 套数非法（`套数大于待收`） |
| 0 ＜ 套数 ＜ 待收 | **不一致**（收货套数对照进失败原因） | **通过**（该维度） |
| 套数 = 待收 | 该维度通过 | 通过 |

### 5.3 字段一致性

| | 预验收 | 批验收 |
|--|--------|--------|
| 已映射字段（除订单行号） | **全部比对**；不等记入不一致 | **不比对** |
| 通过行收货数据来源 | —（不收货） | **发货单已映射值**；未映射可选字段回退订单行 |

### 5.4 结果类型一览

| 类型 | 含义 |
|------|------|
| 通过 | 无任何失败类型 |
| 数据错误 | 解析/必填值无效 |
| 未匹配 | 无对应可收货订单行 |
| 套数非法 | ≤0 或 ＞待收 |
| 不一致 | 仅预验收：已映射字段（含 0＜套数＜待收 的收货套数）与订单行不等 |

---

## 6. 导出

CSV：**原导入文件全部列（原顺序）+ 校验结果 + 失败原因**。

实现须在校验行保留 `sourceRow`（原始列值）。

---

## 7. 批验收确认验收

- 汇总：总种数 / 总套数 / 总册数 / 总码洋 / 总实洋（按通过行、发货单值计算）  
- 确认时：验收单须仍为未开始/进行中  
- 逐行：发货套数 ≤ **实时**待收 → 用发货单数据写入成功；超出 → 该行失败  
- 允许部分成功；失败行可下载异常数据；成功行展示条码（若开启）  
- 文案：`已成功验收 X 条数据，失败 X 条数据。`

---

## 8. 测试要点

1. 入口文案为「批验收」；预验收在其前。  
2. 两边映射五字段缺一不可下一步。  
3. 预验收：＞待收 → 套数非法；＜待收 → 不一致；可与书目不一致并列。  
4. 批验收：＜待收且＞0 → 校验通过；不因码洋/题名等差异失败。  
5. 导出含原列 + 两列结果；多类型结果为分号拼接。  
6. 批验收未全通过不可进确认；确认时待收不足允许部分成功。

## 9. 决策记录

| 决策 | 选择 |
|------|------|
| 架构 | 共享映射 + 分叉校验 |
| 入口改名 | 导入发货单 → 批验收 |
| 批验收步骤 | 四步（含映射） |
| 批验收一致性 | 不校验；收货用发货单数据 |
| 多失败类型 | 同行并列，分号拼接 |
| 导出 | 原列后追加校验结果、失败原因 |
| 确认待收 | ≤ 实时待收可写；允许部分成功 |
