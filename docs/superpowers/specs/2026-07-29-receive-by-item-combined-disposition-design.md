## 1. 背景与目标

选中订单行后打开合并处置面板。原实现用页签分块、各自确认；现改为**同面板纵向展示收/换/退**，统一「确定」一次提交已填处置，成功后关闭面板。

### 1.1 目标

- 选中订单行后打开合并处置面板；内容区纵向三段：收货 → 换货 → 退货，可上下滚动
- 底栏统一「确定」，不区分收/换/退确认按钮；凡填了有效数量的区块一并提交
- 提交成功后**一律关闭**面板（不按 pending 是否为 0 决定）
- 标题仅为「逐条收货/换货/退货」，不拼接订单行号
- 页面底部三操作按钮及独立收/换/退弹窗入口已移除（条码预览弹窗保留）

### 1.2 非目标

- 不抽发货导入共用处置组件（可后续再对齐）
- 不改变收/换/退业务写库语义与待收套数计算公式
- 不改造验收详情撤销收/换/退
- 不做真实后端事务回滚；沿用现有前端 mock 写回
- 本次不更新 `docs/prd.md`（实现后再同步 PRD）

## 2. 方案

**纵向单面板 + 一次确定（已选）**：改造现有 `ReceiveDispositionModal`——去掉页签；顶栏 + 共享套数统计条 + 纵向三区块（可滚动）+ 底栏「关闭 / 预览(条件) / 确定」。一次确定校验通过后，按收 → 换 → 退依次写库。

备选未采用：继续页签分块确认；收货全宽 + 换/退并排；可折叠分区；抽发货导入共用组件。

## 3. 入口与打开/关闭

| 项 | 约定 |
|----|------|
| 打开触发 | 检索结果中点击行或点行单选 → 设选中并打开面板；若检索结果**仅 1 条**，检索完成后自动选中并打开面板 |
| 前置 | 已选当前工作验收单；已完成检索；存在有效选中行 |
| 遮罩 | 打开时全屏遮罩；列表/检索区等底层交互不可用，**不能**在打开状态下切换订单行 |
| 换行 | 先关闭面板，再选另一行 → 重新打开并按新行重置表单 |
| 手动关闭 | 「关闭」按钮或点击遮罩；不提交任何草稿 |
| 成功关闭 | **任一次「确定」写库成功后一律关闭面板**（不再根据 pending 保持打开） |
| 底部按钮 | 页面级「收货 / 换货 / 退货」三按钮已移除 |

关闭后面板不打开时，行选中状态可保留；再次点该行应再次打开。

## 4. 面板结构与字段

### 4.1 壳

- 宽度约 `max-w-4xl`，整体固定高度 `h-[min(90vh,720px)]`；顶栏 / 统计条 / 底栏固定，内容区 `flex-1` 内 `overflow-y-auto`
- 顶栏：标题「逐条收货/换货/退货」+ ×（**不含**订单行号）
- 统计条（只读）：发订套数、已收货套数、已换货套数、已退货套数、**待收货套数**、订单行备注（过长 truncate + 悬停全文）
- **无页签**；内容区自上而下三段分区标题：收货、换货、退货
- 底栏：「关闭」+ 纸质且需分配条码时「预览」+ 统一「确定」

### 4.2 分区 · 收货

按当前验收单资源类型切换，字段与校验与现收货表单一致：

| 类型 | 字段来源 | 说明 |
|------|----------|------|
| 纸质书 | 原纸质收货全部字段（含条码初始号等） | 需要时「预览」→ `BarcodePreviewModal`；确认路径含收货且需分配时走分配结果弹窗 |
| 视听资料 | 原视听收货全部字段 | — |

- 打开时**收货套数默认 = 当前待收货套数**（与原页签一致）
- 预验收草稿仍只带入收货区对应字段；确认收货成功后清除草稿（既有规则）
- **收货备注**为本面板唯一备注输入（纸质/视听均最多 500 字）；即使收货套数为空未参与本次提交，该输入框仍展示，供换/退写库复用

### 4.3 分区 · 换货 / 退货

| 分区 | 字段（界面） |
|------|------|
| 换货 | 换货数量、换货原因（**不展示**换货备注输入框） |
| 退货 | 退货数量、退货原因（**不展示**退货备注输入框） |

**备注统一**：面板仅保留收货区「收货备注」输入框。提交时若换货/退货区块参与写库，其备注字段均取自该「收货备注」同一值（可为空）。

### 4.4 窄屏

表单栅格在窄宽下单列（`grid-cols-1 sm:grid-cols-*`）；三段保持纵向。

## 5. 校验与提交语义

1. 点「确定」：数量为**有效正数**的区块参与提交；空或 0 跳过，且不校验该块原因/收货必填。
2. 收、换、退均无有效数量 → 提示「请至少填写一种处置套数」，不写库、不关面板。
3. **收货套数 + 换货数量 + 退货数量 ≤ 提交时刻待收货套数**；否则失败提示、不写库（对齐发货导入）。
4. 参与提交的收货块：沿用纸质/视听现有必填与条码规则。
5. 参与提交的换/退块：原因必填；备注不单独录入，写库时使用收货备注（长度按收货备注规则校验即可，换/退侧不再单独限制）。
6. 校验全通过后，按 **收货 → 换货 → 退货** 依次调用现有写库（`commitFlow` / `applyAcceptanceSpeciesFlow` + `applyReceiveFlowToPendingRow`）。
7. Mock 原子性：某一流中途失败则停止后续流；已成功流保留（不引入回滚）。
8. 成功提示：统一「提交成功」。
9. 成功后：刷新列表行与页头统计 → **关闭面板**。

**待收货套数** = max(0, 发订套数 − 已收货套数 − 已退货套数)。**不含**已换货套数。

## 6. 组件与改造范围

| 单元 | 职责 |
|------|------|
| `ReceiveDispositionModal.vue` | 去页签；三段纵向；底栏统一「确定」；一次校验后向上抛 `confirm`（payload 含各块表单与有效套数），或等价编排；保留 `close` / `preview` |
| `ReceiveByItemView.vue` | 接一次确认；按收→换→退写库；成功后一律 `dispositionOpen = false`；可去掉分块 `*ResetKey` 与按 pending 保持打开逻辑 |
| `receive-by-item.js` 等 | 业务公式不变；可按需抽「合计 ≤ 待收」校验辅助函数 |
| 条码 / 预验收草稿 | 行为不变，挂在收货区 |
| 旧独立业务 Modal | 页面不挂载；无引用可删 |

**数据流（一次确定成功）**

1. Modal 校验通过 → emit `confirm`  
2. View 按收 → 换 → 退依次 `commitFlow`  
3. 刷新行与页头统计  
4. `dispositionOpen = false`

**检索/换页**：若当前选中行因检索或分页不再存在，关闭面板并清空选中。

---

## 7. 异常处理

| 场景 | 处理 |
|------|------|
| 无当前验收单 / 未检索 | 不打开面板；现有检索提示保留 |
| 三种处置均无有效数量 | 提示；不关面板；不写库 |
| 任一参与块校验失败 / 合计超待收 | 提示；不关面板；不写库 |
| 点遮罩 / 关闭 | 关面板；不提交草稿 |
| 条码预览 | 与现纸质收货一致，不视为提交 |

---

## 8. 验收要点

1. 选行后打开合并面板；无页签；纵向可见收货、换货、退货；内容可滚动。  
2. 标题无订单行号；统计条与字段与现表单一致（含预验收草稿带入收货）；仅收货备注可输入，无换/退备注框。  
3. 底栏仅统一「确定」（及条件「预览」）；一次可提交收+换+退任意组合；换/退备注取自收货备注。  
4. 合计超待收、缺原因、收货缺必填等失败时不写库、不关面板。  
5. 成功后刷新数据并**立即关闭**面板（pending 仍 > 0 也关闭）。  
6. 遮罩下不可换行；纸质条码预览仍可用。

## 9. 测试建议

- 手工：仅收 / 仅换 / 仅退；收+换；收+换+退（合计 = 待收）。  
- 手工：收货默认待收 + 再填换货导致合计超待收 → 应失败。  
- 手工：清空收货套数为空且换/退也为空 → 「请至少填写一种处置套数」。  
- 手工：填收货备注后仅换/退提交 → 写库换/退备注与收货备注一致；界面无换/退备注框。  
- 手工：成功后面板关闭，列表套数已更新；pending 仍 > 0 时也可再点行打开。  
- 手工：遮罩下点列表无效；关闭后换行打开新表单。  
- 回归：预验收草稿带入、条码预览、验收详情按种写回。
