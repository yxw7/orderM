# 订单行列表 — 更换供应商（更改预算）设计

**日期**：2026-07-28  
**状态**：已评审待实现  
**模块**：非连续出版物订单 / 订单行列表  
**关联**：
- 催缺「更换供应商」弹窗交互参照：`ShortageChangeSupplierModal.vue`（本期不改造催缺）
- 催缺侧撤订/更换供应商与订单行联动：`2026-07-28-shortage-cancel-change-supplier-design.md`（已催缺行由催缺入口处理；本功能显式排除）
- 现有 `flowStats`（发/收/换/退/撤订）、`cancelOrders`（订单行整行撤订）、新建订单字段规则

---

## 1. 背景与目标

用户需在订单行列表对未收货部分更换供应商（并可同时改预算）：将未收货套数迁到一条新订单，原行未收货按「更换供应商」记撤订。订单行列表的撤订是整行撤订；催缺撤订可产生部分撤订。为避免与催缺部分撤订纠缠，本功能只允许操作**未生成催缺**的订单行。

### 1.1 目标

- 订单行列表工具栏「更换供应商」：勾选符合条件的行后打开弹窗，确认后生成一条待发订新订单
- 未收货套数迁出；原行未收货写入撤订段（固定原因「更换供应商」），不走整行撤订弹窗
- 新订单继承原单抬头关键字段，弹窗可改订单名称、供应商、预算、备注

### 1.2 非目标

- 不改造催缺管理「更换供应商」与催缺撤订
- 不支持跨订单号批量
- 不提供行内单行操作入口
- 不做真实后端；前端 mock 写 order store

---

## 2. 方案

**订单模块内独立能力（已选）**：专用弹窗 + `order-line-change-supplier.js` 规则函数 + store 一次编排（建新单/新行 + 回写原行）。不与催缺弹窗抽共享组件。

---

## 3. 入口与启用

| 项 | 约定 |
|----|------|
| 位置 | 订单行列表工具栏（与「生成催缺单 / 查重 / 撤订」同级） |
| 文案 | 更换供应商 |
| 操作入口 | 仅工具栏；无行内按钮 |

**按钮启用（全部满足）**

1. 至少勾选 1 行
2. 所选行同一 `orderId`
3. 每行 `lineStatus` ∈ {已发订, 处理中}
4. 每行 `acceptanceStatus` ∈ {待验收, 部分收货, 换货中}
5. 每行 `isShortage` ≠ `是`（未生成催缺）

不满足时按钮禁用；若实现上允许点击，则提示首条不满足原因（与现有批量按钮交互对齐）。

---

## 4. 未收货套数

解析 `flowStats` 为发/收/换/退/撤订后：

```text
未收货套数 = max(0, 发订 − 已收 − 已换 − 已退)
```

- 「换货中」的已换套数**不算**未收货，不迁出
- 生成前：参与行中至少一行未收货 > 0，否则提示「所选订单行没有可迁出的未收货套数」并中止
- 勾选中未收货 = 0 的行：跳过（不迁、不改原行）

---

## 5. 弹窗

复用订单模块 `FormModal`，布局对齐催缺更换供应商（标签右对齐 + 必填红星）。

| 字段 | 必填 | 说明 |
|------|------|------|
| 订单名称 | 是 | 预填为原订单名 +「-1」，可改；长度遵循现有订单名称上限 |
| 供应商 | 是 | 选项按原订单采选方式过滤（`getSupplierOptionsByMethod`） |
| 预算名称 | 条件必填 | 与新建订单一致：交换/捐赠可空，其余必填 |
| 备注 | 否 | 写入新订单备注类字段 |

- 标题：更换供应商
- 确认：生成新订单

**继承（弹窗不编辑）**：订户、馆址、资源类型、语种、采选方式、折扣等取自原订单抬头。因已限制同一订单号，始终生成**恰好 1 条**新订单。

**新订单状态**：待发订（`pending`）。

---

## 6. 提交数据流

Store 方法（如 `changeSupplierGenerateOrder`），前置校验通过后按序执行（原型保证全有或全无）：

1. **新建订单头**  
   继承原单字段；覆盖弹窗中的订单名称、供应商、预算、备注；生成新 `orderId`（现有 `buildOrderId` 规则）。

2. **按参与行新建订单行**（仅未收货 > 0）  
   - 复制书目/资源字段  
   - `sets` 与发订段 = 该行未收货套数；`flowStats` = `{未收货}/0/0/0/0`  
   - `lineStatus` = 待发订；验收/结算与现有待发订行一致  
   - `isShortage` = 否；`budget` / `supplier` 取新订单  
   - 可选内部字段记录来源原订单行号（列表不必展示）

3. **回写原行（专用逻辑，不打开撤订原因弹窗）**  
   - `flowStats` 撤订段 += 未收货套数  
   - 撤订原因固定为「更换供应商」（写入 `cancelReason` / 备注，与现有撤订展示方式对齐）  
   - 若处理后收+换+退+撤 ≥ 发：  
     - 若发订全部进入撤订（无收/换/退）→ 行状态 **已撤订**  
     - 若仍有已收等保留量 → 保留行，验收状态按现有规则趋于完成类（如已无待收则「收货完成」）

4. **收尾**  
   关闭弹窗、清空勾选；成功确认框：「已生成新订单 {orderId}，原行未收货已按更换供应商撤订，是否立即查看？」→ 取消关闭；确定则切换到订单列表。

## 9. 测试要点

1. 启用：同单、行状态、验收状态、非催缺；任一不满足则禁用  
2. 混选含未收货 = 0：只迁有剩余的行  
3. 待验收且全量未收：原行 → 已撤订；新行套数 = 原发订  
4. 部分收货：原行保留已收，撤订段增加；新行套数 = 未收货  
5. 换货中且未收货 = 0：跳过；批内皆 0 → 阻断  
6. 交换/捐赠预算可空；其它采选方式预算必填  
7. 新单为待发订；抬头继承正确；供应商/预算为弹窗值  
8. `isShortage = 是` 的行不可进入本流程（应走催缺侧能力）

---

## 10. 与催缺设计的边界

| 入口 | 适用行 | 迁出/撤订数量口径 |
|------|--------|-------------------|
| 订单行列表「更换供应商」（本文） | `isShortage ≠ 是` | 未收货 = 发 − 收 − 换 − 退 |
| 催缺「更换供应商」/ 撤订 | 已催缺相关行 | 见 `2026-07-28-shortage-cancel-change-supplier-design.md`（催缺套数 − 到货套数） |

两边互不替代；已催缺行必须从本入口排除。
