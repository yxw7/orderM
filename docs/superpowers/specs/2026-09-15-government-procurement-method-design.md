# 采选方式新增「政采」— 设计规格

**日期**：2026-09-15  
**状态**：已确认  
**模块**：采选方式枚举；订单创建/加入订单；换供应商；验收单创建；预验收/发货单匹配  
**关联**：现采供应商规则（代理商 × 书商 × 使用中）；`docs/prd.md` 供应商与采选方式对照表

---

## 1. 背景与目标

系统采选方式当前为：征订目录、捐赠、现采、交存、交换、拍卖。业务需要新增「政采」，规则与「现采」完全一致。

### 1.1 目标

1. 全局采选方式枚举在「现采」之后插入「政采」。
2. 以「现采类」规则组统一现采与政采的供应商、预算及后续流程行为。
3. 订单创建、验收单创建及依赖采选方式的下游流程对政采与现采等价处理（`method` 字面值不同，规则相同）。
4. 实现阶段同步 PRD / 抽屉文案。

### 1.2 非目标

- 不改造现采 Agent 会话流程（仍固定采选方式为「现采」）。
- 不强制将既有 mock 数据批量改为政采（可选增加演示数据，非必须）。
- 不把政采与现采在匹配逻辑上互通（验收/导入等仍按 `method` 字面相等比较）。
- 不新增独立结算、缺货或预算豁免规则。

---

## 2. 方案选型

**已选：方案 2 — 抽象「现采类」规则组**

| 方案 | 说明 | 结论 |
|------|------|------|
| 1 | 枚举 + switch 中政采与现采并列写同一分支 | 可用，但后续同类方式仍易散落硬编码 |
| 2 | 现采/政采归入规则组，供应商与判断走组接口 | **采用** |
| 3 | 全量配置表驱动各采选方式规则 | 对本需求过重 |

---

## 3. 「现采类」规则组

**成员**：`现采`、`政采`。

| 规则 | 行为 |
|------|------|
| 供应商源 | 代理商应用；类型=书商；状态=使用中 |
| 预算名称 | 必填（不在交换/捐赠豁免列表） |
| 折扣 | 选择供应商后默认带出，可修改 |
| 后续流程 | 发订、换供应商、验收创建/匹配、结算等与现采相同；按单据上的 `method` 做相等比较，无需为政采单独分支 |

**澄清**：政采订单行仅匹配 `method=政采` 的验收单；现采同理。二者不跨方式互通。

---

## 4. 枚举与下拉顺序

统一枚举顺序：

1. 征订目录  
2. 捐赠  
3. 现采  
4. **政采**  
5. 交存  
6. 交换  
7. 拍卖  

书目查询「新建订单」「加入订单」检索仍**不含**征订目录，但**含**政采（随过滤后的枚举自动出现）。

筛选类下拉若带「全部」，仍为：`全部` + 上述枚举。

---

## 5. 实现落点

| 落点 | 变更 |
|------|------|
| `html/src/constants/acquisition-methods.js` | 枚举插入「政采」；导出 `isOnSiteLikeMethod(method)`（或等价命名）判断是否现采类 |
| `html/src/modules/order/data/supplier-sources.js` | `getSupplierOptionsByMethod`：现采供应商分支改为现采类判断；征订目录保持与现采相同供应商源 |
| `html/src/modules/order/constants.js` | `BUDGET_OPTIONAL_METHODS` 不变；政采不在列表 → 预算自动必填 |
| 订单/验收 UI | 凡引用统一枚举（`METHOD_OPTIONS` / `ACCEPTANCE_METHODS` 等）的下拉自动出现「政采」 |
| PRD / 抽屉 | 采选方式选项文案与「供应商与采选方式」对照表增加政采一行 |

切换采选方式时：若当前供应商不在新列表中，清空供应商与折扣（沿用现有联动，无新政采专用逻辑）。

---

## 6. 覆盖流程（等价现采）

以下流程在选用「政采」时行为与现采一致（差异仅 `method` 存值为「政采」）：

1. 订单管理新建/编辑订单  
2. 书目查询新建订单、加入订单检索与勾选  
3. 订单行换供应商（单行 / 批量）  
4. 验收管理新建/编辑验收单、批量验收  
5. 预验收、发货单导入等「资源类型 / 语种 / 采选方式 / 供应商须一致」校验  

---

## 7. 文档同步（实现阶段）

- 增量更新 `docs/prd.md` 及相关 `*-prd-data.js` 抽屉内容。  
- 对照表示例：

| 采选方式 | 可选供应商范围 |
|----------|----------------|
| 现采 | 代理商应用中类型为书商且状态为使用中的供应商 |
| 政采 | 同现采 |

---

## 8. 验收标准

1. 采选方式下拉顺序含「政采」，且位于「现采」之后；书目新建/加入订单不含征订目录但含政采。  
2. 选「政采」时供应商列表与「现采」相同。  
3. 「政采」下预算名称必填；提交与校验行为与现采一致。  
4. 可创建 `method=政采` 的订单与验收单；匹配场景下政采订单行仅匹配政采验收单。  
5. 源订单为政采时，换供应商选项仍为书商使用中列表。  
6. 现有现采、捐赠、交换等行为无回归。  

---

## 9. 风险与注意

- 避免在业务代码中新增零散的 `method === '现采'` 特例而不走现采类判断；默认值文案若写死「现采」仅作缺省展示时可保留，但供应商/规则判断须走规则组。  
- 征订目录继续与现采共用书商供应商源，不纳入「现采类」成员集合（仅共享供应商筛选结果）。
