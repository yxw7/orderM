# 查重范围 — 分馆编码前缀通配符设计

**日期**：2026-07-28  
**状态**：已评审待实现  
**模块**：订单管理 / 订单行查重配置弹窗（5.3.5.5）  
**关联**：替换现有「使用中分馆逐条复选 + 关键字联想」查重范围交互

---

## 1. 背景与目标

当前查重范围需勾选大量使用中分馆，操作繁琐。分馆编码按行政区/馆系前缀成组（如首都图书馆系多为 `ST…`），希望用前缀通配符（如 `ST*`）一次覆盖一批分馆。

### 1.1 目标

- 查重范围改为勾选**系统预设**的前缀通配符，支持多选（并集）
- 去掉分馆逐条勾选与关键字联想
- 未选任何通配符时仍按**不限范围**查重
- 提交存档改为 `branchPatterns`，替代 `branchIds`

### 1.2 非目标

- 后缀 / 中间通配、自由输入通配符
- 通配符与分馆逐条勾选并存
- 管理端「通配符配置页」（首版前端常量即可）

---

## 2. 方案

**预设通配符复选列表（方案 A）**：

- 产品写死前缀清单，UI 展示为 `前缀* | 名称`
- 仅支持前缀匹配；多选取并集
- 打开弹窗默认不选（不限范围）

---

## 3. 页面要素

位置：查重配置弹窗，**查重字段下方**。

| 要素 | 说明 |
|------|------|
| 标题 | `查重范围（未选择时按不限范围查重）` |
| 选项 | 预设通配符复选；展示 `ST* \| 首都图书馆` 形式 |
| 容器 | 固定高度，选项多时纵向滚动 |
| 默认 | 不选任何项 |
| 移除 | 分馆关键字搜索、分馆复选、「全部」分馆联动 |

无「必须至少选一个」校验。

## 5. 匹配规则与提交数据

### 5.1 匹配

- 模式形态：`前缀 + *`（来自预设，用户不可编辑）
- 去掉末尾 `*` 得前缀；使用中分馆的 `code` **以该前缀开头**即命中
- 大小写：忽略大小写（与现有查重字段比对习惯一致）
- 多模式：**OR 并集**——命中任一模式即纳入范围
- 未选任何模式：不限范围（不按分馆过滤）

### 5.2 提交与存档

- 提交字段：`branchPatterns: string[]`（如 `['ST*', 'PG*']`）
- 订单行存档：`lastDedupBranchPatterns`
- 废弃：`branchIds` / `lastDedupBranchIds` 及分馆联想相关逻辑

### 5.3 Mock 过滤约定

- 以 `branchPatterns` 为准提交与存档
- 过滤时经馆址管理将模式展开为使用中分馆编码集合，再在**具备分馆编码的数据上**过滤
- 馆藏示例树若仅有名称、无分馆编码：本轮不强行裁剪该节点，避免假精确；正式接口按编码过滤

---

## 6. 异常与边界

| 场景 | 行为 |
|------|------|
| 未选通配符点确定 | 允许，按不限范围 |
| 模式未匹配到任何使用中分馆 | 允许提交；该模式下无命中范围，不弹错 |
| 用户自定义输入 | 不支持（仅预设复选） |
