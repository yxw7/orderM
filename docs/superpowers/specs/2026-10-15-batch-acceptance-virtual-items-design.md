## 1. 背景与目标

### 1.1 背景

图灵对接要求订单侧能创建预验收数据并生成虚拟单册（虚拟条码），实际验收后再转为实际单册。现网 **批量验收** 新建验收单已绑定**订单号**，但只建头、不生成单册，也无收货灌明细能力。验收单管理侧 Excel 预验收仅写草稿，与「整单虚拟单册」不是同一路径。

### 1.2 目标

1. 在批量验收「新增验收单」上增加 **单册生成方式** 三选一，默认保持现网「不生成单册」。  
2. **生成虚拟单册**：新建后按整单可验收行生成**验收行 + 虚拟单册**（系统预分配不重复虚拟条码）。  
3. **不生成单册 / 生成实际单册**：列表「收货」勾选订单行后，分别只写验收行，或验收行 + 实际单册，并回写订单行/验收状态。  
4. 同一张验收单、同一套单册记录，用阶段区分预验收/实际验收；详情按册双视图展示。

### 1.3 非目标

- 图灵调用创建批次 / P2 同步元数据（下期）。  
- 改造验收单管理 Excel 预验收。  
- 勾选部分订单行做「生成虚拟单册」（虚拟模式仅整单）。  
- 新建弹窗增加语种、设为当前工作验收单、自动分配条码开关。

---

## 2. 方案

**采用**：改造批量验收页新建弹窗 + 列表收货窗；验收单与单册一套模型、阶段字段区分。

| 方案 | 说明 | 结论 |
|------|------|------|
| 1 | 以批量验收「新增验收单」为基座扩展 | **采用** |
| 2 | 挂在验收单管理工具栏 | 否决（与「整单 + 订单号」现网批量页不一致） |
| 3 | 从订单列表发起 | 否决（工作台分裂） |

---

## 3. 核心约定

1. **一张验收单**贯通预验收与实际验收，不另建「预验收批次 / 实际验收批次」。  
2. **一套单册记录**，字段 `itemPhase`：`pre`（预验收/虚拟）→ 实际验收后变为 `actual`（原地更新，非复制）。  
3. 详情按册提供 **预验收单册 / 实际验收单册** 视图（过滤同一集合）。  
4. Excel 预验收入口保留在验收单管理，与批量验收本能力并行。  
5. 三种生成方式**均不**在新建弹窗提供「自动分配条码」配置；虚拟条码仅在「生成虚拟单册」时由系统预分配。

## 4. 新建验收单弹窗

### 4.1 字段

| 字段 | 必填 | 说明 |
|------|------|------|
| 验收单名称 | 是 | 同现网 |
| 资源类型 | 是 | 纸质书 / 视听 |
| 采选方式 | 是 | 联动供应商 |
| 供应商 | 是 | 须与订单一致 |
| 订单号 | 是 | 整单键 |
| 发货单号 | 否 | 同现网 |
| 验收备注 | 否 | 同现网 |
| **单册生成方式** | 是 | 单选，见 4.2；**默认：不生成单册** |

不加：语种、设为当前工作验收单、是否自动分配条码。

### 4.2 单册生成方式

| 值 | 文案 | 新建时行为 |
|----|------|------------|
| `none` | 不生成单册 | 仅创建验收单头（绑定订单号）；无验收行、无单册 |
| `virtual` | 生成虚拟单册 | 见 §5.1 |
| `actual` | 生成实际单册 | 新建时与 `none` 相同（只建头）；单册在列表「收货」时生成，见 §5.3 |

### 4.3 提交校验（三种方式共用）

1. 必填项完整。  
2. 订单号存在。  
3. 订单与资源类型、采选方式、供应商一致（无语种校验）。  
4. **建议**：同一订单号若已存在未结束（未开始/进行中）的批量验收单，则拒绝并提示（避免重复灌单）；产品若要放开可在实现期改配置。

---

## 5. 三种模式明细

### 5.1 生成虚拟单册（`virtual`）

新建验收单成功后**立即**执行：

1. 取该订单下订单行状态 ∈ **已发订 / 处理中** 的行。  
2. **验收行**：每行一条（收货套数等取**待收货套数**）。  
3. **虚拟单册**：册数 = 待收货套数 × 套内册数；`itemPhase=pre`；系统预生成**全局不重复**的虚拟条码号。  
4. 不视为业务「已收货」完成态（订单行发订/处理中关系以产品规则为准；默认新建灌入不扣减待收，或按「预占」——**实现计划中与订单待收公式对齐**；规格默认：**灌虚拟单册不改变订单行待收与行状态**，待实际验收/收货再变）。

后续图灵实际验收（接口期）：同一单册更新条码等，`itemPhase` → `actual`。

### 5.2 不生成单册（`none`）

- 新建：只写头。  
- 列表操作列 **收货** → 收货窗口勾选订单行 → 按各行**待收货套数**生成**验收行明细**，**不生成单册**。  
- 订单行状态、验收单状态按实际收货结果变化。

### 5.3 生成实际单册（`actual`）

- 新建：只写头（同 `none`）。  
- 列表操作列 **收货** → 收货窗口勾选订单行 → 按待收货套数生成**验收行明细 + 实际单册**（`itemPhase=actual`）。  
- 订单行状态、验收单状态按实际收货结果变化。  
- 本期真实条码：不在新建时自动分配；收货窗是否录入/分配与现网逐条收货对齐程度在实现计划中定（可先空条码或手工填）。

## 6. 列表与收货窗

### 6.1 批量验收列表

- 保留检索、新增、申请结算、重启等现网能力。  
- **操作列**：对适用行展示 **收货**（至少 `none` / `actual` 模式；`virtual` 是否仍提供补收/改收在实现计划中定，默认虚拟模式以详情查看为主，收货入口可隐藏或仅用于后续实际验收联调）。  
- 建议增加展示：单册生成方式；可选虚拟册数/实际册数（P1）。

### 6.2 收货窗口（`none` / `actual`）

1. 展示本验收单绑定订单下可收货订单行（待收货套数 > 0）。  
2. 多选订单行。  
3. 确认：  
   - `none`：只写验收行；  
   - `actual`：写验收行 + `actual` 单册。  
4. 回写订单行状态与验收单状态（进行中/已结束等规则对齐现有验收语义）。

## 7. 验收单详情

### 7.1 按册双视图

- 页签或筛选：**预验收单册**（`itemPhase=pre`）｜ **实际验收单册**（`itemPhase=actual`）。  
- 底层同一单册集合，禁止复制两套物理行。

### 7.2 按种

- 展示本单验收行；册数汇总可区分预验收册数 / 实际验收册数（展示层），避免与「未生成单册仅有验收行」混淆。

## 11. 测试要点

1. 默认「不生成单册」：新建后详情无按册；收货后仅有验收行、无单册。  
2. 「生成虚拟单册」：已发订/处理中行均有验收行；册数 = Σ(待收套数×套内册数)；虚拟条码互不重复；按册「预验收」可见、「实际验收」为空。  
3. 「生成实际单册」：新建无单册；收货勾选后有验收行 + actual 单册；订单行/验收状态变化。  
4. 订单不存在或与供应商等不一致：不建单。  
5. 同一订单重复建未结束单：按 §4.3 拒绝（若启用）。
