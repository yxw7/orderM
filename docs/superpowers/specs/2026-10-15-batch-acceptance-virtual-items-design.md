## 1. 背景与目标

### 1.1 背景

图灵对接要求订单侧能创建预验收数据并生成虚拟单册（虚拟条码），实际验收后再转为实际单册。现网 **批量验收** 新建验收单已绑定**订单号**，但只建头、不生成单册，也无收货灌明细能力。验收单管理侧 Excel 预验收仅写草稿，与「整单虚拟单册」不是同一路径。

### 1.2 目标

1. 在批量验收「新增验收单」上增加 **单册生成方式** 三选一，默认保持现网「收货后不生成单册」。  
2. **预验收生成虚拟单册**：新建后按整单可验收行生成**预验收行（`linePhase=pre`）+ 虚拟单册（`itemPhase=pre`）**（系统预分配不重复虚拟条码）。  
3. **收货后不生成单册 / 收货后生成单册**：列表「收货」勾选订单行后，分别只写实际验收行（`linePhase=actual`），或实际验收行 + 实际单册，并回写订单行/验收状态。  
4. 同一张验收单；单册用 `itemPhase`、验收行用 `linePhase` 区分预验收/实际验收；详情用「切换预验收」按阶段过滤种册数据。  
5. **冗余虚拟单册清理**：实收「到货每套册数」可小于订购套内册数，导致预验收行按套数删光后仍可能剩 `pre` 册；通过**删预验收行级联清册**（含收货确认）与详情**手动删行/删册**清理（见 §3.7、§5.1、§7.4）。

### 1.3 非目标

- 图灵调用创建批次 / P2 同步元数据（下期）。  
- 改造验收单管理 Excel 预验收。  
- 勾选部分订单行做「预验收生成虚拟单册」（虚拟模式仅整单）。  
- 新建弹窗增加语种、设为当前工作验收单、自动分配条码开关。  
- 虚拟单册软作废/恢复；手动删册时回写订单行待收或行状态。  
- 收货窗内单独「本行不再收」按钮（清理入口在详情 + 收货删行级联）。

## 2. 方案

**采用**：改造批量验收页新建弹窗 + 列表收货窗；验收单贯通；单册 `itemPhase` + 验收行 `linePhase` 区分阶段。

| 方案 | 说明 | 结论 |
|------|------|------|
| 1 | 以批量验收「新增验收单」为基座扩展 | **采用** |
| 2 | 挂在验收单管理工具栏 | 否决（与「整单 + 订单号」现网批量页不一致） |
| 3 | 从订单列表发起 | 否决（工作台分裂） |

---

## 3. 核心约定

1. **一张验收单**贯通预验收与实际验收，不另建「预验收批次 / 实际验收批次」。  
2. **单册**：一套记录，字段 `itemPhase`：`pre` → `actual`（收货确认时对对应数量的册**原地**改阶段，**不复制**单册）。  
3. **验收行**：字段 `linePhase`：`pre` \| `actual`（与 `itemPhase` 语义平行，不混用字段名）。`virtual` 部分实收时**拆行**：预验收行保留剩余套数，另**插入**实际验收行；剩余为 0 则**删除**该预验收行（并按 §3.7 级联清册）。  
4. 详情页签行提供 **切换预验收**：按种按 `linePhase`、按册按 `itemPhase` 过滤。  
5. Excel 预验收入口保留在验收单管理，与批量验收本能力并行。  
6. 三种生成方式**均不**在新建弹窗提供「自动分配条码」配置；虚拟条码仅在「预验收生成虚拟单册」新建时由系统预分配。批量验收收货确认**不**自动分配实际条码：`pre→actual` 时**清空**条码（原虚拟号作废）。  
7. **预验收行 ↔ 单册删除不对称**：  
   - **删除预验收行** → **清空**该行对应仍为 `pre` 的单册（硬删；虚拟条码不回收）。  
   - **删除 `pre` 单册** → **不改动**预验收行（含收货套数）。  
   - 仅 `itemPhase=pre` / `linePhase=pre` 可删；`actual` 不可由此删除。  
   - 手动删除只动验收侧，**不**改订单行待收/行状态；收货路径上订单仍只按实收套数回写，不因级联删册额外改订单。

## 4. 新建验收单弹窗

### 4.1 字段

| 字段 | 必填 | 说明 |
|------|------|------|
| 验收单名称 | 是 | 同现网 |
| 资源类型 | 是 | 纸质书 / 视听 |
| 采选方式 | 是 | 联动供应商 |
| 供应商 | 是 | 须与订单一致 |
| 订单号 | 是 | 整单键 |
| 发货单号 | 否 | 同现网 |
| 验收备注 | 否 | 同现网 |
| **单册生成方式** | 是 | 单选，见 4.2；**默认：收货后不生成单册** |

不加：语种、设为当前工作验收单、是否自动分配条码。

### 4.2 单册生成方式

界面文案（顺序）：**收货后不生成单册** / **收货后生成单册** / **预验收生成虚拟单册**。

| 值 | 文案 | 新建时行为 |
|----|------|------------|
| `none` | 收货后不生成单册 | 仅创建验收单头（绑定订单号）；无验收行、无单册 |
| `actual` | 收货后生成单册 | 新建时与 `none` 相同（只建头）；单册在列表「收货」时生成，见 §5.3 |
| `virtual` | 预验收生成虚拟单册 | 见 §5.1 |

### 4.3 提交校验（三种方式共用）

1. 必填项完整。  
2. 订单号存在。  
3. 订单与资源类型、采选方式、供应商一致（无语种校验）。  
4. **建议**：同一订单号若已存在未结束（未开始/进行中）的批量验收单，则拒绝并提示（避免重复灌单）；产品若要放开可在实现期改配置。

## 5. 三种模式明细

### 5.1 预验收生成虚拟单册（`virtual`）

新建验收单成功后**立即**执行：

1. 取该订单下订单行状态 ∈ **已发订 / 处理中** 的行。  
2. **预验收行**：每个订单行插入一条验收行，`linePhase=pre`；**收货套数 = 待收货套数**；其余展示字段从订单行带出。  
3. **虚拟单册**：册数 = 待收货套数 × 套内册数；`itemPhase=pre`；系统预生成**全局不重复**的虚拟条码号。  
4. 不视为业务「已收货」完成态。规格默认：**灌虚拟单册不改变订单行待收与行状态**；待列表「收货」确认或图灵实际验收后再变。

**允许实际收货（已确认）**：列表操作列展示 **收货**。收货窗勾选订单行并确认后，作为「确认实际收货」（支持部分实收）。对每一勾选行：

1. 本次实收套数记为 `R`；**到货每套册数**记为 `V`（可与订购「套内册数」不同，且允许 `V` 更小）；所需册数 `N = R × V`。  
2. 若该行仍为 `pre` 的单册数 `< N` → **报错**，该行确认失败、不写库。  
3. **单册**：从该行 `pre` 单册中取 `N` 条，原地 `itemPhase: pre→actual`，**条码清空**（原虚拟号作废；批量验收**不**自动分配实际条码）；**不复制**单册。  
4. **验收行（拆分）**：  
   - 原 `linePhase=pre` 行：收货套数改为剩余（原套数 − `R`）；剩余为 0 则**删除**该预验收行，并按 §3.7 **级联删除**该行仍为 `pre` 的单册（避免「行已删、册残留」）。  
   - **新插入**一条 `linePhase=actual` 行，收货套数 = `R`（展示用到货册数语义实现期对齐，至少保证 `N` 册已转 `actual`）。  
5. 按实收回写订单行状态、验收单状态（订单侧不因级联删册额外变化）。  
6. 未勾选行及其 `pre` 验收行 / 单册保持不变。

**冗余册示例**：订 10 套 × 订购套内册数 3 → 预生成 30 册；实收 10 套 × 到货每套册数 2 → 转 20 册；预验收行套数归零被删 → 级联删除剩余 10 册 `pre` 单册。

图灵实际验收（接口期）与上述收货确认在「册数校验 + 单册阶段转换 + 删行级联清册」上对齐；条码是否由对方回写另定。需防双路径重复确认（实现计划做幂等/互斥）。

### 5.2 收货后不生成单册（`none`）

- 新建：只写头。  
- 列表操作列 **收货** → 收货窗口勾选订单行 → 按各行**待收货套数**生成**实际验收行**（`linePhase=actual`），**不生成单册**。  
- 订单行状态、验收单状态按实际收货结果变化。

### 5.3 收货后生成单册（`actual`）

- 新建：只写头（同 `none`）。  
- 列表操作列 **收货** → 收货窗口勾选订单行 → 按待收货套数生成**实际验收行（`linePhase=actual`）+ 实际单册（`itemPhase=actual`）**。  
- 订单行状态、验收单状态按实际收货结果变化。  
- 本期真实条码：批量验收**不**自动分配；收货生成的实际单册条码可先空（与 `virtual` 确认后清空策略一致：本入口不发号）。

## 6. 列表与收货窗

### 6.1 批量验收列表

- 保留检索、新增、申请结算、重启等现网能力。  
- **操作列**：`none` / `virtual` / `actual` **均展示「收货」**（`virtual` 为确认实际收货，见 §5.1）。  
- 建议增加展示：单册生成方式；可选虚拟册数/实际册数（P1）。

### 6.2 收货窗口（按 `itemGenMode`）

1. 展示本验收单绑定订单下可操作订单行（`none`/`actual`：待收货套数 > 0；`virtual`：仍存在 `pre` 单册或待确认实收的行）。  
2. 多选订单行。  
3. 确认：  
   - `none`：只写 `linePhase=actual` 验收行；  
   - `actual`：写 `linePhase=actual` 验收行 + `itemPhase=actual` 单册（条码可空，本入口不自动发号）；  
   - `virtual`：按 §5.1（`N = R × V`；册数不足报错；单册原地 `pre→actual` 并清空条码；验收行拆分；预验收行套数归零则删行并级联清剩余 `pre` 册）。  
4. 回写订单行状态与验收单状态（进行中/已结束等规则对齐现有验收语义）。  
5. 收货窗需能录入或带出**到货每套册数 `V`**（默认可用订购套内册数；允许改小）。实现期定交互（行内字段或统一默认）。

## 7. 验收单详情

### 7.1 布局与切换

- **头信息汇总**（总种数 / 总册数 / 总码洋 / 总实洋等）**不变**，不因「切换预验收」改变。  
- 底部页签仍为：**按种**｜**按册**（同现网）。  
- **页签行右侧**增加复选框：**切换预验收**。  
  - 默认 **不勾选** → 按种展示 `linePhase=actual`；按册展示 `itemPhase=actual`。  
  - **勾选** → 按种展示 `linePhase=pre`；按册展示 `itemPhase=pre`。  
  - 两页签共用同一勾选状态；切换按种 / 按册不丢失。  
- **单册**同一物理集合，靠 `itemPhase` 过滤，禁止为预验收/实际验收各复制一套单册。  
- **验收行**允许同一订单行在部分实收后同时存在 `pre`（剩余）与 `actual`（已实收）两条；切换时各看各阶段。

### 7.2 按册

- 按当前阶段过滤单册明细行（未勾选仅 `itemPhase=actual`，勾选仅 `itemPhase=pre`）。  
- **切换预验收勾选时**（`itemGenMode=virtual`）：支持勾选若干 `pre` 单册后 **删除所选**（任意册数，允许拆套）；按 §3.7 **不改动**预验收行。二次确认；硬删；写 `item.delete` 日志。

### 7.3 按种

- 展示本单对应阶段的验收行（未勾选仅 `linePhase=actual`，勾选仅 `linePhase=pre`），并关联计入同阶段单册。  
- 部分实收后：勾选「切换预验收」可见剩余预验收行；不勾选可见已插入的实际验收行。  
- `itemGenMode=none`（无单册）：与现网「无按册」对齐；头汇总仍按现网规则。  
- **切换预验收勾选时**（`itemGenMode=virtual`）：`pre` 行提供 **删除**（整行剩余一次清）：确认后删除该预验收行，并按 §3.7 **级联清空**该行全部 `pre` 单册。按种删除按「整行/整套剩余」语义，不提供行内改套数后部分删。

### 7.4 冗余虚拟单册清理（详情）

| 入口 | 条件 | 行为 |
|------|------|------|
| 按种 · 删除 | 已勾选「切换预验收」；`linePhase=pre` | 删预验收行 + 级联删该行全部 `pre` 单册 |
| 按册 · 删除所选 | 已勾选「切换预验收」；所选均为 `pre` | 仅删所选单册；预验收行套数等不变 |
| 未勾选「切换预验收」 | — | 不展示上述删除能力 |
| `actual` 种/册 | — | 不可由此删除 |

手动清理与收货级联共用 §3.7；订单待收/行状态均不因手动删除而变。若收货已按套数删行并级联清册，详情侧通常无需再清同一批冗余册；详情能力覆盖「尚未收满套、馆员主动丢掉部分/整行预验收」等场景。

| 9 | 数据层删除 API | `deletePreAcceptanceLine`（级联）、`deletePreItems`（不影响行）；收货拆行复用级联 |

## 11. 测试要点

1. 默认「收货后不生成单册」：新建后详情无按册；收货后仅有 `linePhase=actual` 验收行、无单册。  
2. 「预验收生成虚拟单册」：已发订/处理中行均有 `linePhase=pre` 预验收行（收货套数=待收货套数）；册数 = Σ(待收套数×套内册数)；虚拟条码互不重复；默认不勾「切换预验收」时按种/按册为空（尚无 `actual`）；勾选后可见预验收种册。  
3. `virtual` 部分实收（`V` = 订购套内册数）：插入 `actual` 验收行、预验收行套数减少（为 0 则删除并级联清剩余 `pre` 册——若 `N` 已用尽全部 `pre` 则无残留）；仅 `N` 册 `pre→actual` 且条码被清空；未勾选「切换预验收」可见已转实际的册且总册数不因复制翻倍。  
4. `virtual` 实收册数所需 `N` 大于剩余 `pre` 单册数：报错、不写库。  
5. `virtual` 到货每套册数小于订购：订 10×3→30 册，实收 10×2→转 20；预验收行删除且剩余 10 册被**级联删除**；无「无行孤儿册」。  
6. 详情按种删 `pre` 行：行与该行全部 `pre` 册消失；同订单行已有 `actual` 行/册不动；订单待收不变。  
7. 详情按册删部分 `pre` 册：册消失；预验收行套数不变；订单待收不变。  
8. 未勾选「切换预验收」无删除入口；`actual` 不可删。  
9. 「收货后生成单册」：新建无单册；收货勾选后有 `actual` 验收行 + actual 单册（条码可空）；订单行/验收状态变化。  
10. 订单不存在或与供应商等不一致：不建单。  
11. 同一订单重复建未结束单：按 §4.3 拒绝（若启用）。

## 12. 决策记录

| 决策 | 结论 |
|------|------|
| 入口 | 批量验收「新增验收单」 |
| 单据 | 同一验收单，不拆预验收/实际验收批次 |
| 单册 | 一套记录 + `itemPhase`；收货时对应数量原地 `pre→actual`，不复制 |
| 验收行 | `linePhase`；`virtual` 新建为预验收行；部分实收拆行（插 `actual`，减/删 `pre`） |
| 详情阶段切换 | 页签行「切换预验收」；按种按 `linePhase`、按册按 `itemPhase`；头汇总不变 |
| 三选一 | 收货后不生成单册 / 收货后生成单册 / 预验收生成虚拟单册 |
| 预验收生成虚拟单册 | 整单；预验收行（套数=待收）+ 虚拟单册 + 系统虚拟条码 |
| 虚拟模式收货 | **允许**部分实收；`N = R × V`（`V`=到货每套册数，可小于订购）；册数不足报错；单册转阶段并**清空条码**；验收行拆分；删预验收行时**级联清剩余 `pre` 册** |
| 条码 | 批量验收不自动分配实际条码；仅新建虚拟时预分配 |
| 收货后生成单册 | 新建只建头；收货窗勾选行后写 `actual` 验收行 + actual 单册 |
| 收货后不生成单册 | 收货窗只写 `actual` 验收行 |
| 不加字段 | 语种、设为当前、自动分配条码开关 |
| 图灵 | 本期不做接口 |
| 冗余虚拟册清理时机 | 收货删预验收行时级联清；其余由详情预验收视图手动删（不在收货窗做「不再收」） |
| 删除不对称 | 删预验收行 → 级联清对应 `pre` 册；删 `pre` 册 → 不影响预验收行 |
| 详情删除入口 | 仅「切换预验收」：按种整行删；按册可任意册数勾选删 |
| 手动删除与订单 | 只动验收侧；不改订单待收/行状态 |
| 删除形态 | 硬删；不软作废；虚拟号不回收 |
