# 订户配置馆藏查重范围与优先所属馆

**日期**：2026-08-20  
**状态**：已确认  
**模块**：订户管理、订单行查重（5.3.5.5 / 5.3.5.6）  
**关联**：
- 查重范围多选：`2026-08-06-dedup-branch-collection-multiselect-design.md`
- 查重结果合并面板：`2026-08-06-dedup-result-panel-merge-design.md`

---

## 1. 背景与目标

馆藏查重的「所属分馆 / 所属馆藏地」目前在查重配置弹窗（`DedupConfigModal`）中每次临时选择，不利于按业务订户固化范围，也无法表达「单件优先展示所属馆」的排序诉求。

### 1.1 目标

1. 将馆藏查重范围配置迁到**订户**新增/编辑（及查看）中。
2. 已选分馆支持**优先级排序**；该顺序即「优先展示的所属馆」，不另建独立选项集。
3. 调用馆藏查重时，按**当前馆员关联订户**合并后的分馆/馆藏地检索有无馆藏单件。
4. 查重结果「单件」页签：左侧馆藏树一级节点与右侧单件列表均按优先所属馆排序。
5. 查重弹窗**删除**整块「查重范围」UI。

### 1.2 非目标

- 真实编目检索接口实现细节（原型 mock；请求/存档须带合并后的范围字段）
- 改造订单查重比对逻辑（仍按现有订户可见订单行规则）
- 订户列表新增独立「查重设置」入口
- 订单行详情、书目浮动窗等其它单件列表的排序（本版仅查重结果面板）

---

## 2. 方案选型

**已选：订户表单内嵌「范围 + 可排序分馆」（方案 1）**

- 订户表单增加查重范围区块；分馆多选 + 上移/下移定序；馆藏地多选。
- 查重弹窗只保留重复类型与查重字段；提交时由前端按馆员关联订户合并范围写入请求。

未选：独立查重设置页（入口割裂）；仅靠多选标签顺序定优先级（改序体验差）。

---

## 3. 订户表单与数据字段

### 3.1 入口

- `SubscriberFormModal`（新增/编辑）：在现有字段下方增加「查重范围」区块。
- 订户详情：只读展示同样字段。
- 订户列表：本版**不新增列**（避免过宽）；配置仅在表单/详情可见。

### 3.2 字段

| 字段 | 存储键 | 控件 | 规则 |
|------|--------|------|------|
| 所属分馆 | `dedupBranchCodes: string[]`（**有序**） | `SearchableMultiSelect` + 已选分馆排序（上移/下移） | 选项同现查重弹窗（使用中四级分馆）；展示「编码 \| 名称」；可空 |
| 所属馆藏地 | `dedupCollectionCodes: string[]` | `SearchableMultiSelect` | 已选分馆 → 下级馆藏地并集；未选分馆 → 全部馆藏地；变更分馆后剔除无效项；可空 |

### 3.3 优先级

- 不另选「优先所属馆」集合；`dedupBranchCodes` 数组下标越小越优先。
- UI：已选分馆以有序列表展示，支持上移/下移（实现默认上移/下移；拖拽为可选增强，非必须）。

### 3.4 校验

- 两字段均可空（该订户空配置 = 不限制该订户侧范围贡献）。
- 不强制「配置了分馆必须配置馆藏地」。
- 分馆停用：编辑时保留已选项展示（对齐订户「所属馆」停用仍可选的既有模式）。

## 4. 查重弹窗与请求合并

### 4.1 弹窗变更（`DedupConfigModal`）

- **删除**「查重范围」整块（所属分馆、所属馆藏地及 `showBranchScope` 相关逻辑）。
- 仅保留：重复类型、查重字段。
- 弹窗提交**不再**由用户选择 `branchCodes` / `collectionCodes`。

### 4.2 合并算法

查重提交前，取当前馆员**关联订户列表**（与现有可查看/关联订户同一数据源，**保持列表既有顺序**），计算：

1. **`branchCodes`（有序）**：按订户顺序依次拼接各订户 `dedupBranchCodes`；同一分馆编码**首次出现保留**（全局优先序）。
2. **`collectionCodes`（并集）**：各订户 `dedupCollectionCodes` 去重并集（顺序不敏感）。
3. 若合并后两数组皆空 → **不限范围**（与现弹窗未选一致；请求传空数组或省略，与现网约定一致即可）。
4. 仅当重复类型为「不限」或「馆藏查重」时将范围带入馆藏检索；「订单查重」不传范围。

### 4.3 请求与落库

- 馆藏查重调用携带合并后的 `branchCodes`（有序）、`collectionCodes`。
- 原型：写入订单行 `lastDedupBranchCodes` / `lastDedupCollectionCodes`（延续现字段，来源改为合并结果）；mock 可按范围裁剪馆藏结果或仅存档。

### 4.4 边界

- 馆员无关联订户：沿用现有权限提示；若仍进入查重，范围按空（不限）。
- 单行与批量查重：均使用上述「关联订户合并」规则（不按各订单行所属订户分别取配置）。

---

## 5. 查重结果排序（单件页签）

使用本次合并得到的有序 `branchCodes` 作为优先所属馆（可回落读取行上 `lastDedupBranchCodes`）。

| 区域 | 规则 |
|------|------|
| 左侧馆藏树 | 一级「机构/所属馆」节点按优先序靠前；不在优先列表中的馆排在后面（保持其原相对顺序稳定） |
| 右侧单件列表 | 按单件「所属馆」映射到分馆优先序；同馆内保持原相对顺序；未匹配优先列表的排后 |

- 所属馆与 `branchCodes` 的对应：通过馆藏主数据（分馆编码/名称）映射；无法映射的单件/树节点视为「未在优先列表」。
- 先按四级叶子（或未关联馆藏地）过滤，再排序。
- 优先序为空：不额外重排，保持原序。

## 6. 组件与数据流

| 位置 | 变更 |
|------|------|
| `SubscriberFormModal` / 详情 | 查重范围 UI（分馆有序 + 馆藏地） |
| `subscriber-manage.js` | 模型增加 `dedupBranchCodes`、`dedupCollectionCodes`；示例数据补齐 |
| `current-librarian` 或独立工具 | `resolveLibrarianDedupScope()`：关联订户合并分馆优先序 + 馆藏地并集 |
| `DedupConfigModal` | 删除查重范围 |
| `order` store `submitDedup` | 提交前合并范围并传入 `performOrderLineDedup` |
| `DedupResultDrawer` | 树一级节点与单件列表按优先序排序 |
| PRD | 同步 5.3.5.5（去弹窗范围）、订户配置、5.3.5.6 排序 |

**数据流**：订户保存有序分馆/馆藏地 → 馆员查重（弹窗只选类型/字段） → 确定时按关联订户合并范围 → 馆藏检索带范围 → 结果面板按分馆优先序展示树与单件。

---

## 7. 验收要点

1. 订户可配置分馆顺序与馆藏地；详情只读可见。
2. 查重弹窗无「查重范围」。
3. 馆员关联多订户时：请求/存档范围为馆藏地并集，分馆顺序为按订户顺序拼接去重。
4. 结果面板馆藏树一级节点与单件列表按优先分馆靠前。
5. 各关联订户范围皆空 → 不限范围，行为与现「未选」一致。
