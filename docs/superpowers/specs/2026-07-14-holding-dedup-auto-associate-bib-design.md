# 馆藏查重返回后自动关联书目记录号设计

**日期**：2026-07-14  
**状态**：已确认  
**关联模块**：订单行列表 · 馆藏查重（5.3.5.5 / 5.3.5.6）  
**实现落点（原型）**：`html/src/modules/order/data/dedup.js` → `performOrderLineDedup`

---

## 1 背景

订单行列表支持馆藏查重。馆员可在查重结果面板中手动将某条馆藏书目的记录号「关联」到订单行（写入 `bibRecordNo`）。

当订单行尚未关联书目（`bibRecordNo` 为空）且馆藏查重有匹配结果时，默认将**结果第一条**写入订单行，可减少一次手动关联；已有书目记录号的订单行保持不变，避免覆盖馆员已选关联。

## 2 业务决策

| 决策项 | 结论 |
|--------|------|
| 时机 | 馆藏查重接口返回并落库时立刻自动关联（查重配置点「确定」成功后），无需打开结果面板 |
| 批量 | 逐行独立判断：每行各自取**本行**馆藏结果的第一条 |
| 提示 | 静默更新列表「书目记录号」列，不弹 toast / 确认框 |
| 落点 | 方案 1：在查重结果落库路径（`performOrderLineDedup`）一并处理 |

## 3 触发与写入规则

### 3.1 触发时机

在馆藏查重结果写入订单行之后立刻执行，与「馆藏重复」标识同一轮落库。

- 重复类型为「馆藏查重」或「不限」：走馆藏结果路径，可触发自动关联  
- 重复类型仅为「订单查重」：不执行自动关联

打开「馆藏查重结果」面板时**不再**执行自动关联（已在接口返回时处理）。

### 3.2 逐行写入条件

同一订单行须**同时满足**以下条件才写入：

1. 本轮执行了馆藏查重  
2. 当前订单行 `bibRecordNo` 去空格后为空  
3. `holdingDedupResults` 至少有一条，且第一条带有效 `bibRecordNo`（去空格后非空）

### 3.3 写入内容

将 `holdingDedupResults[0].bibRecordNo` 写入该订单行的 `bibRecordNo`。

「第一条」= 接口返回顺序的首条，与结果面板书目列表排序一致。

### 3.4 不写入的情况

| 情况 | 行为 |
|------|------|
| 书目记录号已有值 | 不覆盖（即使与结果第一条不同） |
| 馆藏结果为空 | 不改 `bibRecordNo` |
| 第一条无有效书目记录号 | 不改 `bibRecordNo` |
| 仅订单查重 | 不涉及馆藏自动关联 |

## 4 与手动关联 / 结果面板

- 手动「关联 / 取消关联」规则不变：关联写入该书目记录号；取消关联清空 `bibRecordNo`  
- 若查重时已自动关联第一条：打开结果面板时，该行操作显示「取消关联」，其余行显示「关联」  
- 取消关联后再跑馆藏查重且有结果：因书目记录号为空，将再次自动关联第一条  
- 已有书目记录号再查重：不改写（含馆员曾手动关联非第一条的情况）

## 5 列表与体验

- 查重配置弹窗关闭后，「书目记录号」与「馆藏重复」标识一并刷新  
- 无额外成功提示  

## 6 原型实现要点

在 `performOrderLineDedup` 中，对每个目标行在写入 `holdingDedupResults` / `holdingDuplicate` 之后：

```text
if checkHolding
  and isBlank(target.bibRecordNo)
  and holdingDedupResults[0]?.bibRecordNo 有效
then
  target.bibRecordNo = holdingDedupResults[0].bibRecordNo
```

不新增独立 store 编排步骤；结果面板组件无需为自动关联增加生命周期钩子。

同步修订 PRD `5.3.5.6` 业务规则：补充「馆藏查重返回后，书目记录号为空则自动关联结果第一条」。

## 7 不在本期范围

- 按单件数量优先选择关联书目（非「第一条」策略）  
- 自动关联成功的 toast / 批量汇总提示  
- 打开结果面板时的二次自动关联兜底  
- 真实后端接口契约变更（本期以前端模拟落库为准；正式后端应对齐同一规则）
