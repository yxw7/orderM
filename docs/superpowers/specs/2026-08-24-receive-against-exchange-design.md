## 1. 背景与目标

订单行换货后，书商补货到货时馆员仍在逐条收货弹窗做收货。需要可选地将本次收货优先（或在超出可普通容量时被动）冲销换货记录：订单行已收↑、已换↓，并更新换货记录表「未到货」记录。

### 1.1 目标

- 订单行已换货套数 > 0 时，在收货备注后展示复选框「优先对换货记录收货」（默认不勾选）
- 勾选：本次收货**换货优先**拆分；不勾选：**普通优先**，仅当收货量超过「待收 − 已换」时剩余部分冲销换货
- 换货冲销部分：写回订单行 + FIFO 更新换货记录表；普通部分：仅普通收货写库

### 1.2 非目标

- 不改造发货单导入、批量验收等其他收货入口
- 不改变待收货套数公式（仍 = 发订 − 已收 − 已退，**不含**已换）
- 不改造验收详情撤销收/换/退
- 不做真实后端事务回滚；沿用前端 mock 写回

## 2. 已确认产品选择

| 问题 | 选择 |
|------|------|
| 显示条件 | 订单行已换货套数 > 0（不论换货记录是否已到货） |
| 复选框文案 | 「优先对换货记录收货」 |
| 复选框位置 | 收货备注下方（纸质 / 视听相同） |
| 默认状态 | 不勾选 |
| 作用范围 | 仅逐条收货处置弹窗 |
| 勾选时优先级 | 先冲已换，剩余普通收货 |
| 不勾选时优先级 | 先普通（上限 = 待收 − 已换），剩余再冲已换 |
| 多条换货记录 | 按换货时间早→晚冲「未到货」；已撤销跳过 |

## 3. UI

- 仅当 `summary.exchange > 0`（或行上 `exchangedSets > 0`）时渲染复选框
- 位于收货区「收货备注」输入框之后、换货分区之前
- 无已换货时不占位、不提交相关字段
- 本次无有效收货套数时，复选框状态忽略（不参与拆分）

## 4. 拆分公式

记：

- `R` = 本次收货套数（有效正数）
- `P` = 待收货套数
- `E` = 已换货套数
- `Ncap` = max(0, `P` − `E`)（可普通收货容量）

约束：`R ≤ P`（及现有收货必填 / 与换退合计 ≤ 待收）。

### 4.1 不勾选（普通优先）

```
normal = min(R, Ncap)
offset = R - normal
```

### 4.2 勾选（换货优先）

```
offset = min(R, E)
normal = R - offset
```

### 4.3 示例（发订 10 / 已收 0 / 已换 3 / 已退 0 → P=10，Ncap=7）

| 勾选 | R | normal | offset |
|------|---|--------|--------|
| 否 | 5 | 5 | 0 |
| 否 | 9 | 7 | 2 |
| 是 | 2 | 0 | 2 |
| 是 | 9 | 6 | 3 |

## 5. 写库语义

一次确定仍按 **收货 → 换货 → 退货**；本规格只扩展收货段。

### 5.1 普通部分（`normal > 0`）

与现网 `commitFlow('receive', normal, …)` 一致：

- 订单行 / 验收按种：已收货套数 += `normal`
- **不**改已换货套数、**不**改换货记录表

### 5.2 换货冲销部分（`offset > 0`）

1. 订单行 / 验收按种：已收货套数 += `offset`；已换货套数 -= `offset`（不低于 0）
2. 换货记录表：按该订单行、状态「未到货」、`exchangeTime` 升序，依次冲销：
   - 本条可冲 = 换货套数 − 已到货套数（或等价剩余未到货量）
   - 写入到货套数累加；到货批次 = 当前工作验收单号
   - 剩余未到货归零时状态 →「已到货」
   - 已撤销记录跳过
3. 若记录侧可冲总量 < `offset`（数据不一致）：按实际可冲量更新记录；订单行已换扣减与实际冲销量对齐；mock 可 `alert` 提示不一致

实现建议：在 `receive-by-item.js`（或邻近模块）提供 `splitReceiveAgainstExchange(R, P, E, againstExchange)` 与 `applyExchangeOffsetToRecords(orderLine, offset, arrivedBatch)`；`ReceiveByItemView` 在收货分支先拆分再依次写库。

### 5.3 Payload

`ReceiveDispositionModal` 的 `confirm` 在收货块有效时增加：

- `againstExchange: boolean`（无复选框时视为 `false`）

## 7. 异常处理

| 场景 | 处理 |
|------|------|
| 已换 = 0 | 不显示复选框；行为与现网纯收货相同 |
| 收+换+退合计超待收 | 与现网一致，提示、不写库、不关弹窗 |
| 无有效收货套数 | 忽略复选框 |
| 换货记录可冲 < offset | 见 §5.2.3 |

---

## 8. 验收要点

1. 已换 > 0：收货备注下出现「优先对换货记录收货」，默认不勾；已换 = 0 不出现  
2. 不勾且 R ≤ Ncap：只加已收；已换与换货记录不变  
3. 不勾且 R > Ncap：先普通，剩余冲换货（已换↓ + 记录 FIFO）  
4. 勾选：先冲换货，剩余普通收货  
5. 多条未到货按时间早→晚；已撤销跳过  
6. 仅逐条收货弹窗；发货导入等入口无此复选框
