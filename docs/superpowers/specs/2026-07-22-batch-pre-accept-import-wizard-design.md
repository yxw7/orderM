# 验收单管理 — 预验收与批验收合并导入向导

**日期**：2026-07-22  
**状态**：已评审待实现  
**模块**：采访验收 / 验收单管理  
**关联**：
- 取代验收单管理现有「导入发货单」（ISBN/题名匹配、异步任务路径）
- 侧栏「批量验收」本期不改造（闲置/弱化）
- 条码分配复用逐条收货 / 验收单配置逻辑

---

## 1. 背景与目标

### 1.1 背景

- 一张书商发货单常含 **多个订单号** 的订单行。
- **验收单管理**下的验收单可对 **不同订单号** 的订单行验收，并可分配条码。
- 侧栏 **批量验收** 现有模型为「一验收单一订单号」且无法生成条码，不适合直接承载「整张多订单发货单」导入。
- 业务需要：先按订单行号核对发货单与系统差异，再在字段一致时批量收货。

### 1.2 目标

在 **验收单管理** 提供单一 **「导入发货单」** 向导（同步），四步完成：

1. 上传文件（预设模板）  
2. 数据校验（匹配 + 四字段比对，可导出）  
3. 数据预览（展示待验收订单行）  
4. 确认验收（整批收货写入当前验收单）

其中「预验收」能力体现在第 ② 步校验与导出；「批验收」能力体现在第 ④ 步确认收货。

### 1.3 非目标（本期不做）

- 列名映射（使用固定模板表头）
- 异步导入任务 / 进度续办 / 导入任务列表扩展
- 批验收换货、退货
- 按订单号拆成多个验收单
- 改造侧栏「批量验收」的一单一订单模型或为其补条码
- 书商订单号与系统订单号映射维护
- 恢复或并存旧版 ISBN/题名匹配导入向导

---

## 2. 方案选型

| 方案 | 说明 | 结论 |
|------|------|------|
| 挂侧栏批量验收 | 须按订单号拆单，且无条码 | 不采用 |
| **挂验收单管理 + 单一向导** | 一张发货单进一个可跨订单号的验收单，可条码 | **采用** |
| 预验收 / 批验收两个入口 | 交互分裂 | 不采用；合并为一步向导四步 |

侧栏「批量验收」本期保留列表/结算作历史即可，导入能力不迁入。

## 3. 入口与前置条件

### 3.1 按钮

验收单管理操作区：**「导入发货单」**（替换原异步导入发货单入口）。

### 3.2 启用规则

| 条件 | 结果 |
|------|------|
| 勾选 **恰好 1 条**，状态为 **未开始** 或 **进行中** | 按钮可点 |
| 勾选 0 / 多条 / 已结束 | 按钮置灰 |

点击后携带该验收单上下文进入全页（或大弹窗）导入向导。

### 3.3 顶栏固定信息

向导全程展示所选验收单：验收单号、名称、资源类型、语种、供应商、发货单号等（与现有导入顶栏一致即可）。

---

## 4. 预设导入模板

**不做列名映射。** 提供「下载模板」；上传文件必须匹配固定表头。

| 列名 | 必填 | 说明 |
|------|------|------|
| 订单行号 | 是 | 精确匹配系统订单行 |
| 码洋 | 是 | 与系统订单行比对 |
| 实洋 | 是 | 与系统订单行比对 |
| 收货套数 | 是 | 与系统待收/收货数量逻辑比对；验收写入用此套数 |
| 套内册数 | 是 | 与系统比对；视听资料对应套内件数，模板说明中注明 |

### 4.1 文件校验

- 仅允许 `.xls` / `.xlsx`
- 表头缺列、列名不符、无数据行 → 阻断并提示，不进入第 ② 步
- 单元格空值、非数字（金额/套数/册数）→ 记为该行校验失败

---

## 5. 向导步骤

```text
① 上传文件 → ② 数据校验 → ③ 数据预览 → ④ 确认验收
```

全程 **同步** 处理（本期无后台任务）。

### 5.1 ① 上传文件

- 下载空白模板  
- 选择并上传发货单  
- 通过表头/格式校验后进入 ②  

### 5.2 ② 数据校验

对每一数据行：

1. 以 **订单行号** 在 **全库可收货订单行** 中查找（状态 ∈ {已发订, 处理中}，待收套数 > 0）。  
2. 建议附加与验收单一致的过滤：供应商、资源类型、语种等（与验收单上下文一致，避免串单）；具体过滤字段与现有逐条收货池对齐。  
3. 命中后比对四字段：**码洋、实洋、收货套数、套内册数**（数值比较规则：去空白；金额按小数规范化比较，如保留 2 位）。  
4. 另校验：发货单「收货套数」> 0 且 ≤ 该行待收套数。

| 行结果 | 条件 |
|--------|------|
| 通过 | 命中且四字段一致且套数合法 |
| 未匹配 | 无对应可收货订单行 |
| 不一致 | 命中但四字段任一不等 |
| 套数非法 | 套数 ≤ 0 或大于待收 |
| 数据错误 | 解析失败等 |

**页面**：汇总通过/失败条数；失败行列表含原因；支持 **导出校验结果**（含订单行号、结果、系统值、发货单值、失败原因）——此即原「预验收」产出。

**导航**：存在失败行时仍可停留在 ② 导出；**不可进入 ③**（或进入 ③ 但确认验收始终不可用——推荐直接禁止进入 ③，强制先修文件）。

**本期约定**：任一失败行 → **禁止进入第 ③ 步**。

### 5.3 ③ 数据预览

仅当第 ② 步 **全部行通过** 后进入。

- **只展示**匹配到的 **订单行业务信息**（如：馆址、订单行号、订单号、题名、ISBN、码洋、实洋、套内册数、待收套数、本次收货套数等）。  
- **不展示**系统值 vs 发货单值并排差异表（因能进入本步时已全部一致）。  
- 「下一步」进入 ④。

### 5.4 ④ 确认验收

- 再次只读汇总：将收货行数、总套数等。  
- 用户点「确认验收」：  
  - **整批写入**当前验收单的收货（仅收货，无换货/退货）。  
  - 收货套数取发货单列（与系统一致）。  
  - 码洋/实洋按发货单（与系统一致时等价）。  
  - 若验收单开启自动分配条码：按现有纸质书收货条码规则分配；分配失败则 **整批回滚**（或确认前预检失败——原型可提示失败原因且不写库）。  
- 成功后：验收单状态未开始 → 进行中（与现有导入/收货联动一致）；关闭向导并刷新列表。

### 5.5 整批阻断（批验收）

确认验收前/时，只要存在任一不可收行（理论上 ③ 已保证全通过，确认时仍建议做一次实时待收复核）：

- **整批不提交**  
- 提示失败原因；可返回或关闭后重新上传  

与既有「提交时订单行冲突校验」精神一致：确认瞬间再查实时待收，不足则整批失败。

## 6. 数据流（简述）

```text
验收单管理勾选 1 条
  → 打开向导（带 acceptanceSnapshot）
  → 上传固定模板文件
  → 解析行 → 按 orderLineNo 查可收货池 → 四字段比对
  → 全通过 → 预览订单行
  → 确认 → 写收货（+ 可选条码）→ 更新验收单
```

## 9. 测试要点

1. 未勾选 / 多选 / 已结束 → 导入按钮不可用。  
2. 表头错误 → 停留上传步并提示。  
3. 含未匹配行 → 校验失败，不可进预览；可导出。  
4. 四字段不一致 → 同上。  
5. 收货套数 > 待收 → 失败。  
6. 全部通过 → 预览仅订单行信息 → 确认后验收单有收货、状态正确。  
7. 同一文件含多个订单号 → 可写入同一验收单。  
8. 开条码的验收单 → 确认后分配条码或失败整批不写。  
9. 确认瞬间待收被占 → 整批失败提示。

## 10. 决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 挂载模块 | 验收单管理 | 可跨订单号、可条码；发货单不必拆单 |
| 批量验收页 | 本期闲置 | 一单一订单且无条码，与发货单现实冲突 |
| 入口 | 单一「导入发货单」 | 预验收与批验收合并 |
| 模式选择步 | 取消 | 固定四步：上传→校验→预览→确认 |
| 勾选 | 打开向导前必须勾选 1 条 | 确认验收需要验收单上下文 |
| 列映射 | 不做 | 预设五列表头 |
| 异步 | 不做 | 本期同步向导 |
| 差异时批验收 | 整批阻断 | 仅全一致可预览/确认 |
| 预览内容 | 仅订单行信息 | 能进入预览即已无差异 |
| 写入 | 仅收货 | 不做换退 |
