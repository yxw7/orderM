# 催缺配置 · 馆址 / 供应商 / 订单号范围条件

**日期**：2026-09-28  
**状态**：待评审  
**范围**：设置 → 催缺配置（`/shortage-config`）新增/编辑/查看弹窗；配置数据模型与范围匹配辅助函数  
**关联**：
- 现有催缺配置模块 `html/src/modules/shortage-config/`
- 馆址选项 `useSiteSelectOptions` / 馆址管理启用馆址
- 订单主数据（订单号存在性与订户归属校验）

---

## 1. 背景与目标

### 1.1 背景

催缺配置当前仅支持「订户 + 触发条件（发订天数 / 发订日期区间）+ 是否启用 + 备注」。业务需要在同一配置上进一步限定自动催缺的订单范围：按馆址、供应商、订单号。

### 1.2 目标

1. 在新增/编辑/查看弹窗中增加三个**非必填**范围条件：按馆址（多选）、供应商（多选）、订单号（单行文本）。
2. 订单号有值时校验：存在、属于当前订户；若同时选了馆址/供应商，做交叉冲突校验。
3. 提供纯函数 `matchesShortageScope`，表达「未填不限制、已填 AND」语义，供后续自动生成复用。
4. 查看弹窗只读展示上述条件；列表不加新列、不加检索项。

### 1.3 非目标

- 不实现真实定时/任务型自动生成催缺（本期只落配置与匹配语义）。
- 不改列表列、筛选、排序。
- 不改订户唯一性、触发条件必填等既有规则。

---

## 2. 方案

**采用**：表单扩展 + 范围匹配纯函数（方案 2）。

| 方案 | 说明 | 结论 |
|------|------|------|
| 1 | 仅表单字段与校验 | 否决（匹配语义无法复用/可测） |
| 2 | 表单 + `matchesShortageScope` | **采用** |
| 3 | 方案 2 + 列表列/检索 | 否决（超出「查看展示、列表不加列」约定） |

---

## 3. 界面

**入口**：催缺配置 → 新增配置 / 编辑配置 / 查看配置（`ShortageConfigFormModal`）。

**字段位置（布局 B）**：紧挨在「订户」下方、启用开关与触发条件之前，形成「先定订户与范围，再定是否启用与何时催」。

| 字段 | 控件 | 必填 | 说明 |
|------|------|------|------|
| 按馆址 | `SiteMultiSelect` 多选 | 否 | 选项 = 馆址管理中已启用馆址名称（`useSiteSelectOptions`） |
| 供应商 | `SiteMultiSelect` 多选 | 否 | 选项 = `SUPPLIER_OPTIONS`（`@/modules/order/constants`），与订单表单一致；不新建平行列表 |
| 订单号 | 单行文本 | 否 | 单个订单号；placeholder「请输入订单号」 |

**查看模式**：三字段只读；空值展示「—」；已选多选展示已选项（与现有只读多选风格一致）。

**列表**：列定义不变；不在「触发条件」列拼接范围摘要。

**分区文案**（可选轻量提示）：三字段上方可用一行辅助说明「催缺范围（均非必填）」；不引入独立卡片容器，保持现有表单行布局。

## 4. 数据模型

配置行新增：

| 字段 | 类型 | 空值语义 |
|------|------|----------|
| `sites` | `string[]` | `[]` = 不限制馆址 |
| `suppliers` | `string[]` | `[]` = 不限制供应商 |
| `orderId` | `string` | `''` = 不限制订单号 |

持久化前：`orderId` trim；`sites` / `suppliers` 去重、去空串。

`rowToForm` / `buildShortageConfigPayload` / mock 样例同步包含上述字段。既有字段（订户、触发、启用、备注、状态、排序）不变。

---

## 5. 校验

校验时机：点击「提交」时，与现有 `validateShortageConfigForm` 一并执行。

### 5.1 既有规则（不变）

- 订户必选；同一订户配置不可重复。
- 触发条件按所选类型校验天数或日期区间。

### 5.2 订单号

| 条件 | 结果 |
|------|------|
| `orderId` 为空 | 通过（不校验） |
| 订单不存在 | 错误：`订单号不存在` |
| 订单存在但 `order.subscriber` ≠ 当前表单订户 | 错误：`订单号不属于当前订户` |

订户未选时：若已填订单号，仍先报订户错误；订单号校验可在订户有效后再执行（避免无订户上下文的误导文案）。

### 5.3 交叉冲突（订单号 × 馆址 / 供应商）

仅当订单号有值、订单存在且订户匹配后执行：

| 条件 | 结果 |
|------|------|
| 已选馆址，且订单 `site` ∉ `sites` | 错误：`订单号与所选馆址不匹配` |
| 已选供应商，且订单 `supplier` ∉ `suppliers` | 错误：`订单号与所选供应商不匹配` |
| 馆址或供应商未选 | 该侧不做交叉校验 |
| 仅馆址+供应商、无订单号 | 不做交叉校验 |

馆址与供应商可同时报错（一次提交展示全部相关错误）。

## 6. 范围匹配语义

### 6.1 组合规则（A + B）

自动催缺命中条件（概念上全体 AND）：

1. 配置订户 = 目标订户  
2. `matchesShortageScope(config, target)` 为 true  
3. 满足所选触发条件（发订天数或发订日期区间）  
4. 配置处于启用/使用中  

未配置的范围字段不参与限制。

### 6.2 `matchesShortageScope(config, target)`

`target` 至少提供 `site`、`supplier`、`orderId`（订单或订单行均可）。

```
if config.sites.length > 0 and target.site not in config.sites → false
if config.suppliers.length > 0 and target.supplier not in config.suppliers → false
if config.orderId and target.orderId !== config.orderId → false
else → true
```

三者皆空 → 恒 true。

### 6.3 本期交付

实现并导出该纯函数（放在 `shortage-config-manage.js`），可用简单单元断言或页面内联注释样例验证。不接线真实调度任务。

## 8. 验收要点

1. 三字段均可留空并成功保存；空配置行为与改造前一致。  
2. 非法订单号、跨订户订单号无法提交，文案正确。  
3. 订单号与所选馆址/供应商冲突时无法提交，文案正确。  
4. 查看弹窗展示已保存的范围；列表外观无新增列。  
5. `matchesShortageScope` 对「部分填写 / 全空 / 全填」行为符合 §6.2。
