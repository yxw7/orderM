# 验收单详情按种 · 发/收/换/退/撤订五段展示

**日期**：2026-09-15  
**状态**：已确认  
**模块**：验收单详情页「按种」页签（纸质书 / 视听）  
**关联**：
- 订单行 `flowStats`（发/收/换/退/撤订）
- 逐条验收列表 `counts` 五段展示
- `html/src/modules/acceptance/data/detail-utils.js`（按种 counts 解析写回）

---

## 1. 背景与目标

验收单详情「按种」列表列名与数值格式仍为四段：纸质书为「发/收/换/退数」、视听为「发/收/换/退套数」，单元格如 `2 / 2 / 0 / 0`。订单管理与逐条验收已统一为「发/收/换/退/撤订」五段，详情按种需对齐，避免馆员误以为验收单不体现撤订套数。

### 1.1 目标

1. 纸质书、视听「按种」列名统一为 **发/收/换/退/撤订**。
2. 单元格展示与写回格式改为五段：`发 / 收 / 换 / 退 / 撤`。
3. 解析与写回工具支持第五段 `cancelled`（撤订）；收/换/退写回不改动撤订段。
4. 实现阶段同步 PRD / 抽屉文案。

### 1.2 非目标

- 不改「按册」页签列与数据。
- 不在验收详情新增撤订操作入口。
- 不改订单行列表、逐条验收列表（已是五段名）。
- 不改「换/退/撤销收货原因」列语义（撤销收货 ≠ 撤订）。

## 3. 列名与数值格式

| 资源类型 | 原列名 | 新列名 |
|----------|--------|--------|
| 纸质书 | 发/收/换/退数 | 发/收/换/退/撤订 |
| 视听资料 | 发/收/换/退套数 | 发/收/换/退/撤订 |

展示格式：`{ordered} / {received} / {exchange} / {returned} / {cancelled}`  
示例：`2 / 1 / 0 / 0 / 1` 表示发订 2、收货 1、换货 0、退货 0、撤订 1。

兼容：字符串不足五段时，缺省段按 `0` 解析。

---

## 4. 数据流

### 4.1 解析 `parseSpeciesCounts`

返回对象增加 `cancelled`：

| 字段 | 含义 | 来源 |
|------|------|------|
| ordered | 发订 | 段 0 或 `row.ordered` |
| received | 收货 | 段 1 或 `row.received` |
| exchange | 换货 | 段 2 或 `row.exchange` |
| returned | 退货 | 段 3 或 `row.returned` |
| cancelled | 撤订 | 段 4 或 `row.cancelled` |

对象字段路径优先时：若行上已有 `received` / `exchange` / `returned` 等字段，一并读取 `cancelled`（缺省 0）。

### 4.2 格式化与写回

- `formatSpeciesCounts` 输出五段字符串。
- `updateSpeciesCounts(row, patch)` 合并 patch 后写回五段；`row.cancelled` 同步落字段。
- 现有收货 / 换货 / 退货 / 撤销收货写回只 patch 对应段，**不覆盖** `cancelled`。

### 4.3 Mock

`acceptanceSpeciesRows` / `acceptanceAvSpeciesRows` 及新建行默认 `counts` 改为五段；至少 1～2 行 `cancelled > 0` 便于演示。新建 upsert 默认值由 `0 / 0 / 0 / 0` 改为 `0 / 0 / 0 / 0 / 0`。

## 6. 验收标准

1. 纸质书、视听「按种」表头均为「发/收/换/退/撤订」。
2. 列表单元格均为五段数字；缺省历史四段数据打开后按第五段 0 展示（经 format 写回后为五段）。
3. 收/换/退/撤销收货后，该行撤订段保持原值不变。
4. Mock 中存在撤订 > 0 的示例行可见。
5. PRD / 抽屉按种列文案与页面一致。
6. 「按册」页签无回归。

---

## 7. 风险与注意

- 「撤订」套数与「撤销收货原因」不同：前者为 flowStats 第五段，后者为收货被撤销的原因文案；勿混用字段。
- 验收详情本期不提供撤订写入入口；第五段仅展示与透传，来源可为 mock 或后续与订单行同步。
