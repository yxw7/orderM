# 逐条收货 — 收/换/退合并处置面板设计

**日期**：2026-07-29  
**状态**：已评审待实现  
**模块**：采访验收 / 逐条收货  
**关联**：
- 页面：`html/src/modules/acceptance/views/ReceiveByItemView.vue`
- 现有弹窗：`PaperReceiveModal.vue`、`AvReceiveModal.vue`、`ReceiveExchangeModal.vue`、`ReceiveReturnModal.vue`、`BarcodePreviewModal.vue`
- 数据流：`receive-by-item.js`（`commitFlow` / `applyReceiveFlowToPendingRow`）、`acceptance-detail.js`（`applyAcceptanceSpeciesFlow`）
- 对照交互：发货单导入处置区可同时填收/换/退（本需求为**分区块独立确认**，非一次整单提交）

---

## 1. 背景与目标

当前逐条收货需先选订单行，再点底部「收货 / 换货 / 退货」分别打开独立弹窗，切换操作成本高。用户希望选中订单行后展开的面板**同时展示**三种操作内容。

### 1.1 目标

- 选中订单行后自动打开合并处置面板，左右分栏同时展示收货、换货、退货
- 三块各自确认提交，互不捆绑
- 提交成功后按待收货套数决定保持打开或自动关闭
- 移除页面底部三个操作按钮及三个独立入口弹窗（条码预览弹窗保留）

### 1.2 非目标

- 不做一次确定同时提交收+换+退（与发货导入整行处置不同）
- 不改变收/换/退业务写库语义与套数计算公式
- 不改造验收详情撤销收/换/退
- 不做真实后端；沿用现有前端 mock 写回

---

## 2. 方案

**左右分栏合并面板（已选）**：新增 `ReceiveDispositionModal`，顶栏 + 共享套数统计条；左栏完整收货表单（纸质/视听按类型切换）；右栏上换货、下退货；各区块独立「确认」按钮。面板打开时带全屏遮罩，底层列表不可点。

备选未采用：纵向分区滚动（首屏不易一眼见换/退）、顶栏锚点纵向（实现更重且非「一眼全见」）。

---

## 3. 入口与打开/关闭

| 项 | 约定 |
|----|------|
| 打开触发 | 检索结果中点击行或点行单选 → 设选中并打开面板 |
| 前置 | 已选当前工作验收单；已完成检索；存在有效选中行 |
| 遮罩 | 打开时全屏遮罩；列表/检索区等底层交互不可用，**不能**在打开状态下切换订单行 |
| 换行 | 先关闭面板，再选另一行 → 重新打开并按新行重置表单 |
| 手动关闭 | 「关闭」按钮或点击遮罩；不提交任何区块草稿 |
| 自动关闭 | 任一确认成功后，若该行**待收货套数 = 0** → 关闭面板 |
| 保持打开 | 确认成功后待收货套数仍 > 0 → 保持打开，刷新统计与行数据，清空**本次已提交**区块表单 |
| 底部按钮 | 移除「收货 / 换货 / 退货」三按钮 |

关闭后面板不打开时，行选中状态可保留（与现单选一致）；再次点该行应再次打开（实现时：选中已是该行则仍应打开面板）。

---

## 4. 面板结构与字段

### 4.1 壳

- 宽度约 `max-w-6xl`，高度受限可滚动（建议主体区 `max-h` + 分栏内各自滚动，避免整页失控）
- 顶栏：标题「订单行处置」+ 订单行号 + ×
- 统计条（只读，随成功提交刷新）：发订套数、已收货套数、已换货套数、已退货套数、**待收货套数**、订单行备注（备注过长 truncate + 悬停全文，对齐现收货弹窗）
- 底栏：仅「关闭」（无统一「确定」）

### 4.2 左栏 · 收货

按当前验收单资源类型切换，**完整保留**现有弹窗字段与校验：

| 类型 | 来源 | 区块操作 |
|------|------|----------|
| 纸质书 | `PaperReceiveModal` 全部字段（含条码初始号等） | 确认收货；需要时「条码预览」→ 现有 `BarcodePreviewModal` |
| 视听资料 | `AvReceiveModal` 全部字段 | 确认收货 |

### 4.3 右栏 · 换货 / 退货

| 区块 | 字段 | 操作 |
|------|------|------|
| 换货（右上） | 换货数量*、换货原因*、换货备注（与现 `ReceiveExchangeModal` 一致） | 确认换货 |
| 退货（右下） | 退货数量*、退货原因*、退货备注（与现 `ReceiveReturnModal` 一致） | 确认退货 |

### 4.4 窄屏

宽度不足时改为纵向堆叠：收货 → 换货 → 退货；字段与确认语义不变。

---

## 5. 校验与提交语义

- 每次只提交**被点击确认的那一块**；另两块未提交输入保留，不参与本次写库。
- 本区块校验失败：提示（沿用 `alert` 或现组件方式），面板不关，其他区块输入保留。
- 套数：须为有效正数，且不超过提交时刻该行待收货套数；否则失败不写库。
- 换货/退货：数量填写后原因必填（与现弹窗一致）。
- 收货：沿用纸质/视听现有必填与条码规则。
- 成功路径仍调用现有编排：`applyAcceptanceSpeciesFlow` + `applyReceiveFlowToPendingRow`（经页面侧现有 `commitFlow` 封装即可）。

**待收货套数**：与现逐条收货行上 pending 一致（提交后由 `applyReceiveFlowToPendingRow` 等刷新）；自动关闭条件以刷新后的 pending === 0 为准。

## 6. 组件与改造范围

| 单元 | 职责 |
|------|------|
| `ReceiveDispositionModal.vue`（新） | 遮罩壳、顶栏、统计条、左右分栏布局、关闭；对外 `open` / `row` / 资源类型与条码配置；向上抛 `confirm-receive` / `confirm-exchange` / `confirm-return` / `close` / `preview-barcode` |
| 收货表单区块 | 从纸质/视听 Modal 抽出可嵌入表单（或 modal 内联复用），避免三套字段分叉 |
| 换货/退货区块 | 复用现字段与原因常量（`EXCHANGE_REASON_OPTIONS` / `RETURN_REASON_OPTIONS`） |
| `ReceiveByItemView.vue` | 选行打开合并面板；移除底部三按钮与三个独立业务弹窗挂载；保留条码预览弹窗与成功后 pending=0 关面板逻辑 |
| 旧三个业务 Modal | 页面不再挂载；若无其他引用可删除或保留为薄包装（实现阶段按引用情况处理，以无死代码为准） |

**数据流（成功一次确认）**

1. 区块校验通过 → emit confirm  
2. View `commitFlow(flow, sets, form)`  
3. 刷新选中行与页头套数统计  
4. 清空该区块表单；更新面板统计条  
5. 若 pending === 0 → `dispositionOpen = false`，否则保持 `true`

**检索/换页**：若当前选中行因检索或分页不再存在，关闭面板并清空选中（与「遮罩下不可换行」不冲突：仅在面板已关或数据失效时处理）。

---

## 7. 异常处理

| 场景 | 处理 |
|------|------|
| 无当前验收单 / 未检索 | 不打开面板；现有检索提示保留 |
| 区块校验失败 | 提示；不关面板；不写库 |
| 套数非法或超过待收 | 提示失败；不写库 |
| 点遮罩 / 关闭 | 关面板；不提交草稿 |
| 条码预览 | 与现纸质收货一致，不视为提交 |

---

## 8. 验收要点

1. 选行后自动打开合并面板，左收货、右换/退同时可见（纸质/视听字段与旧弹窗一致）。  
2. 遮罩期间无法点击列表切换订单行；换行须先关闭再选。  
3. 可分别确认收 / 换 / 退；一次确认只生效一种。  
4. 成功后统计与行数据刷新；pending > 0 保持打开并清空已提交块；pending = 0 自动关闭。  
5. 页面底部三按钮已移除。  
6. 纸质需分配条码时，「条码预览」仍可用。  
7. 窄屏下纵向堆叠仍可完成三种操作。
