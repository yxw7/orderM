# 订单行列表检索 — 定价区间与多选条件设计

**日期**：2026-08-05  
**状态**：已实现  
**模块**：非连续出版物订单 / 订单行列表 / 筛选查询  
**关联**：PRD `5.3.5.1 筛选查询`；现有 `OrderLineSearchPanel.vue`、`order-line-filter.js`

---

## 1. 背景与目标

订单行展开检索需支持按定价区间定位订单行；同时行状态、供应商、预算由单选改为多选，便于一次勾选多个值过滤。

### 1.1 目标

- 「订单重复」后增加「定价」区间条件（下限 / 上限）
- 「行状态」「供应商」「预算」改为多选检索
- 同步更新 PRD §5.3.5.1 与订单管理 PRD 抽屉文案

### 1.2 非目标

- 其他检索字段改多选
- 按币种过滤或币种换算
- 真实后端 API（前端 mock 过滤）

---

## 2. 方案

**定价双输入 + 三字段复用 SiteMultiSelect（已选）**

- 定价：同一格内「下限 - 上限」两个数字输入
- 行状态 / 供应商 / 预算：复用现有 `SiteMultiSelect` 标签多选

---

## 3. 定价区间

### 3.1 页面要素

| 项 | 约定 |
|----|------|
| 位置 | 展开检索区，「订单重复」同行下一列 |
| 标签 | 定价 |
| 控件 | 下限输入框 + `-` + 上限输入框 |
| 占位 | 可用「最低」「最高」或留空 |

### 3.2 匹配规则

对订单行 `price` 做数值比较（`parseFloat`），**不区分币种**。

| 填写情况 | 行为 |
|----------|------|
| 两端都空 | 不按定价过滤 |
| 只填下限 | `price >= 下限` |
| 只填上限 | `price <= 上限` |
| 两端都填 | `下限 <= price <= 上限`（闭区间） |
| 下限 > 上限 | 提示错误（如「定价下限不能大于上限」），**不发起检索** |

- 行上 `price` 为空或无法解析为数值时：若已填写任一端定价条件，则该行不匹配
- 输入限制：最多两位小数（可复用 `sanitizeDecimalInput`）

### 3.3 检索模型

| 字段 | 类型 | 默认 |
|------|------|------|
| `priceMin` | `string` | `''` |
| `priceMax` | `string` | `''` |

---

## 4. 行状态 / 供应商 / 预算多选

### 4.1 页面要素

| 字段 | 控件 | 说明 |
|------|------|------|
| 行状态 | `SiteMultiSelect` | 选项：待发订、已发订、处理中、已关闭；去掉「全部」 |
| 供应商 | `SiteMultiSelect` | 选项来源不变（当前馆员关联订户资源类型 ∩ 供应商） |
| 预算 | `SiteMultiSelect` | 选项来源不变（当前馆员关联订户预算并集） |

位置、展开/收起逻辑不变。未选任何项时占位「请选择」。

### 4.2 匹配规则

| 填写情况 | 行为 |
|----------|------|
| 数组为空 | 该字段不过滤（等同原「全部」） |
| 数组非空 | 行字段值落在选中集合内即保留（**或**） |

### 4.3 检索模型

| 字段 | 原类型 | 新类型 | 默认 |
|------|--------|--------|------|
| `lineStatus` | `string`（含「全部」） | `string[]` | `[]` |
| `supplier` | `string` | `string[]` | `[]` |
| `budget` | `string` | `string[]` | `[]` |

---

## 5. 交互

- 条件变更不自动检索，需点「检索」
- 「检索」前先做定价下限 > 上限校验；失败则 `alert` 并中止
- 「重置」清空全部条件（含 `priceMin`/`priceMax` 与三多选数组）并恢复列表
