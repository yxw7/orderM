# 订单列表批量发订

**日期**：2026-09-15  
**状态**：已确认  
**模块**：非连续出版物订单 · 订单列表（`OrderListPanel` / 发订 5.2.5.5）  
**关联**：
- `docs/prd.md` §5.2.5.5 发订
- `html/src/prd/order-manage-prd-data.js`（item 5.2.5.5）
- 现有单笔发订：`order-issue.js`、`IssueOrderModal.vue`

---

## 1. 背景与目标

订单列表已支持操作列单笔「发订」，工具栏仅有新建、撤订、批量导出。馆员需对多笔「待发订」订单逐一点行内发订，效率低。

### 1.1 目标

1. 在「新建订单」后增加工具栏「发订」，支持勾选多笔待发订订单批量发订。
2. 批量与单笔共用发订备注弹窗；批量一次填写的备注写入每个**成功**发订的订单。
3. 批量逐单提交：**某一单失败只提示，不回滚已成功单**（非整批事务）。
4. 统一约束：订单下至少有 1 条「待发订」订单行才可发订（单笔与批量一致）。

### 1.2 非目标

- 不强制发订前查重。
- 不新增独立批量发订向导 / 预览页。
- 不改变撤订、导出、删除、加入订单、换供应商、验收、催缺的既有规则。
- 不要求勾选订单同供应商 / 同订户等额外一致性（仅状态与行数）。

## 2. 方案选型

**已选：方案 1 — 复用发订弹窗 + 工具栏启用条件 + 逐单部分成功**

| 方案 | 说明 | 结论 |
|------|------|------|
| 1 | 工具栏「发订」+ 共用备注弹窗；启用条件置灰；逐单发订、部分失败只提示 | **采用** |
| 2 | 独立批量发订向导（预览列表 → 备注 → 结果明细） | 过重，本期不做 |
| 3 | 无弹窗直接发订（备注恒空） | 与备注方案不符 |

---

## 3. 入口与启用条件

### 3.1 入口

| 入口 | 行为 |
|------|------|
| 工具栏「发订」 | 位于「新建订单」右侧、「撤订」左侧；对当前勾选订单批量发订 |
| 操作列「发订」 | 保留；仅待发订订单显示（现状） |

### 3.2 工具栏「发订」启用条件

须**全部**满足，否则按钮**置灰**（不可点击，不弹「请先勾选」类告警；对齐订单行批量查重启用模式）：

1. 至少勾选 1 条订单；
2. 勾选订单的 `orderStatus` 全部为待发订（`pending`）；
3. **每一个**勾选订单下，至少存在 1 条 `lineStatus === '待发订'` 的订单行。

混选非待发订、或任一无待发订行 → 置灰。

### 3.3 单笔「发订」空行约束

- 显示条件仍为订单状态待发订。
- 点击时若该单无待发订订单行：不打开备注弹窗，`alert`「订单下无待发订订单行，无法发订」。
- 与批量启用条件语义一致，避免单笔可发空单、批量不可的分裂。

## 4. 备注弹窗与提交

### 4.1 弹窗

- 单笔与批量共用现有「请填写发订备注：」弹窗；备注可空。
- 批量：一次填写；同一备注写入本批每个**成功发订**订单的 `issueRemark`。
- `issuer`、`issueTime`：各成功单写入；同一批可共用同一次确认时刻。

### 4.2 单笔成功语义（不变，叠加空行校验）

前置通过后：

1. 订单状态 → 已发订（`ordered`）；
2. 写入 `issueTime`、`issuer`、`issueRemark`；
3. 该订单下所有「待发订」订单行 → 「已发订」，并写入行 `issueTime`。

### 4.3 批量提交语义（逐单、非事务）

1. 打开弹窗时将勾选订单快照为待处理列表，顺序为当前筛选结果中自上而下的出现顺序。
2. 确认后按该顺序**逐单**执行与单笔相同的发订逻辑。
3. **某一单失败**：不回滚已成功单；**继续**处理后续单。
4. 关闭弹窗；清空本页勾选；刷新列表。

### 4.4 结果提示（批量）

| 结果 | 提示要点 |
|------|----------|
| 全部成功 | 如「已发订 N 个订单」 |
| 部分成功 | 如「成功 N 个，失败 M 个：{订单号}（原因）；…」 |
| 全部失败 | 列出失败订单号与原因；不提示为成功 |

### 4.5 提交时失败原因（二次校验）

打开弹窗后、确认时订单可能已变，单笔失败原因包括但不限于：

- 订单不存在；
- 已非待发订；
- 已无待发订订单行。

文案可复用或贴近现有「仅待发订状态的订单可发订」及 §3.3 空行提示。

---

## 5. 与周边功能边界

| 功能 | 边界 |
|------|------|
| 查重 | 不强制发订前查重；发订成功后行不可再查重（现状） |
| 撤订 / 导出 / 删除 | 规则不变；仅共用勾选列 |
| 加入订单、换供应商·加入 | 候选仍仅待发订；发订成功后自然退出候选池 |
| 验收 / 催缺 / 结算 | 仍从已发订起算，无新分支 |

## 7. 验收要点

- [ ] 「新建订单」右侧出现「发订」；未勾选 / 混选非待发订 / 任一无待发订行时置灰。
- [ ] 勾选多笔合法待发订订单 → 弹备注 → 全部成功变已发订，行同步，同备注写入。
- [ ] 批量中某单提交时已非待发订或空行：该单失败提示，其余成功单保留已发订，不整批回滚。
- [ ] 操作列发订：无待发订行时不打开弹窗并提示。
- [ ] 撤订、查重、加入订单等行为无回归。
