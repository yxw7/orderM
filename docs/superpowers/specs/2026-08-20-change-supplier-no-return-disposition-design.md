# 更换供应商 — 源行不引入「退货」决策说明

**日期**：2026-08-20  
**状态**：已决策（不做）  
**模块**：非连续出版物订单 / 订单行更换供应商（行内 + 工具栏批量）  
**关联**：
- `2026-08-19-change-supplier-join-existing-order-design.md`（新建/加入订单）
- PRD `5.3.5.12` 更换供应商
- 退货管理 / 逐条收货退货流程

---

## 1. 背景

曾设想在更换供应商弹窗中，对源订单行「可迁出套数」增加处理方式单选：

- **撤订**：沿用现逻辑（记撤订段 + 撤订原因）
- **退货**：记退货段 + 退货原因，并在退货管理生成对应退货记录

目标侧（新建订单 / 加入订单）拟保持不变。

## 2. 决策

**不在更换供应商弹窗引入「撤订 / 退货」单选。**

源行对可迁出套数**仅执行撤订**；退货能力继续留在验收侧（逐条收货/换货/退货、退货管理等）完成。

## 3. 理由

1. **上下文不匹配**：退货管理记录通常依赖退货批次、发货单号等验收/发货上下文；更换供应商入口只有订单行与目标订单信息，无法自然带出这些字段。
2. **硬造批次会失真**：若在本弹窗自动生成专用批次或把发货单号置空，退货清单语义与真实收货后退货不一致，后续对账与查询易混淆。
3. **业务边界清晰**：更换供应商的本质是「迁出待处理套数并换供应商下单」；未收货可迁出套数用撤订记账更贴切。退货属于货物处置，应在已有退货入口处理。

## 4. 维持的现状（不变）

| 项 | 规则 |
|----|------|
| 可迁出套数 | max(0, 发订 − 已收 − 已退 − 已换) |
| 源行回写 | 撤订段累加迁出套数；撤订原因 = 弹窗原因 |
| 原因控件 | `ReasonSelect` 类型为撤订 |
| 目标侧 | 新建待发订订单或加入已有待发订订单（见既有设计） |
| 备注 | 可选；追加至源订单行备注 |

## 5. 非目标 / 明确不做

- 更换供应商弹窗增加「撤订 / 退货」单选
- 本入口写 `flowStats` 退货段或写入退货管理清单
- 本入口切换为退货原因参数

若未来要在「换供应商」场景支持退货，应先明确验收/发货关联，并另开专项设计，而不是在本弹窗内补字段凑合。

## 6. 对 PRD / 实现的影响

- **无需改**现有 `5.3.5.12` 与更换供应商实现（本决策确认维持撤订-only）。
- 本文档仅作产品决策留档，避免后续重复提出同一方案时遗忘边界。
