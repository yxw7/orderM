# 订户推导的机构数据隔离

**日期**：2026-10-26  
**状态**：待评审  
**定位**：修订 `2026-10-15-institution-data-isolation-revision-design.md`（下称「10-15」）的**读墙来源与账号态**；保留双轨与「验收单头无订户」。  
**并列**：`2026-10-21-library-data-isolation-design.md`（library 主轴）仍为备选、**未采用**。  
**范围**：订单管理系统全模块（采访业务、订户/馆员、设置、货币）

**前提已确认**：

- 机构轨读墙**不**依赖业务中台「馆员所在馆」；机构集合由**关联订户所属 institution** 推导。
- 保留订户轨 / 机构轨双轨；验收单头**不**挂 `subscriberId`；同机构内机构轨可跨订户。
- 无关联订户 ⇒ 无采访单据 / 验收结算 / 馆址条码等业务读写（含原「有馆无订户」账号）；**例外**：订户列表、馆员列表对 U0 开放租户全量（见 §4.2），用于维护订户并完成「馆员↔订户」关联，从而产生首个 U1。
- 新建验收单时，关联订户推出的机构合集必须**唯一**，否则报错不可建。
- 待结算**新增结算**、结算失败**重新结算**：所选验收单的 `institutionId` 必须全部相同，否则不可提交；结算批次机构取该共同机构（且须 ∈ 订户机构合集）。

## 1. 背景与目标

### 1.1 为何成文

10-15 以所在馆倒推**单一机构**服务机构轨；S2（有订户、无所在馆）无法进入验收单管理 / 结算 / 馆址等。曾评估「订户主轴」（验收挂订户、读墙只认关联订户）与「机构小补丁」（仅给 S2 恢复订户机构合集 fallback）。

评审收敛为：**小补丁骨架 + 所在馆彻底退出读墙**——任何人（含原 S1）的机构范围一律由关联订户推导；并调整订户列表 / 馆员列表展开规则；验收新建要求机构合集唯一。

### 1.2 目标

1. 业务单据仍持久化 `institutionId` / `institutionCode`（归属、审计、单号前缀）。
2. **机构轨**上下文 = `resolveSubscriberInstitutionIds()`（关联订户 → 机构合集）；**不**调用所在馆解析作权限。
3. **订户轨**读过滤仍仅关联订户；写机构取所选/相关订户所属机构。
4. 菜单作用域仍为 `subscriber` / `institution` / `tenant`。
5. 单号前缀仍用 `institutionCode`；历史前缀不改号。
6. 账号就绪收敛为 U0 / U1（见 §3）；未满足前置时按模块提示（见 §7）。
7. 订户列表 / 馆员列表：U0 均为租户**全量**可读写（含关联）；U1 收窄为关联订户所属机构下的**全部**订户 / 馆员。

### 1.3 非目标

- 验收单头增加订户字段；纯订户读墙（单据列表按订户 ID 硬过滤机构轨单据）。
- 以 library 为主墙或改单号前缀为 library code（见 10-21，未采用）。
- 改造业务中台账号/分馆同步协议（所在馆可继续同步与展示，**不作读墙**）。
- 不在本版拍板「订单与 MARC 映射」「退换撤订原因参数」是否改为机构级（保持与 10-15 相同的待定）。

## 2. 方案选型

| 方案 | 说明 | 结论 |
|------|------|------|
| 1. 订户主轴 | 验收挂唯一订户；读墙一律关联订户；所在馆非权限 | 否决（本轮未采用；作对照） |
| **2. 订户推导机构墙** | 保留双轨与验收无订户头；机构集合来自关联订户；所在馆非权限；新建验收合集须唯一 | **采用**（本文） |
| 3. 双通道 | 有订户按订户/合集；无订户有所在馆仍按所在馆 | 否决（S1 也不看所在馆） |
| 4. 仅 S2 fallback | 有分馆仍单一所在馆；无分馆才用订户合集 | 否决（与「S1 也不考虑所在馆」冲突） |

## 3. 账号态与作用域模型

### 3.1 组织模型

与 10-15 相同：

```
租户 (tenant)
 └── 机构 (institution)     ← 机构墙字段与单号前缀；本方案读墙来源改为订户推导
      └── 馆区 (campus)
           └── 分馆 (library)  ← 馆员「所在馆」可展示；不作读墙
                └── 馆藏地 (location)
```

| 概念 | 职责 |
|------|------|
| 租户 | 登录域；货币等全局配置 |
| 机构 | 验收/结算/馆址/条码等归属与读墙字段；单据机构快照；单号前缀 |
| 分馆 | 可选展示/同步；**不**倒推权限机构 |
| 订户 | 订户轨读写边界；**并**推导机构轨机构合集 |

### 3.2 账号就绪（U0 / U1）

| 状态 | 条件 | 读/写原则 |
|------|------|-----------|
| **U0** | 无关联订户 | 订户轨与机构轨业务单据：**否/否**。**例外**：订户列表、馆员列表可查看/写入租户内**全部**订户/馆员，并可做「订户关联馆员」（仍受角色是否可进该页约束）。 |
| **U1** | 有 ≥1 关联订户 | **订户轨**：按关联订户查看与写入。**机构轨**：按订户→机构合集查看；写入见 §3.4 / §4。订户/馆员列表见 §4.2（收窄为关联订户所属机构范围）。 |

相对 10-15 四态：

| 旧态 | 映射 |
|------|------|
| S0 | U0 |
| S1（有馆、无订户） | **U0**（所在馆不再赋予机构轨） |
| S2 / S3 | U1（有无所在馆不改变读墙） |

实现可保留 `branchId` 展示；**不以**所在馆或馆员缓存 `institutionId` 为权限权威。

### 3.3 解析函数

| 函数 | 规则 |
|------|------|
| `getAssociatedSubscriberIds()` / 名称列表 | 当前馆员关联订户；U0 为空 |
| `resolveSubscriberInstitutionIds()` | 关联订户各自 `institutionId` 去重合集；**机构轨读墙与新建前置** |
| `resolveOrderInstitutionId(subscriberId)` | 该订户所属机构；订户轨写快照 |
| `resolveHomeInstitutionId()` | **废除作权限**；可选保留仅供 UI 展示所在馆/机构 |

**明确禁止**：

- 用所在馆倒推机构充当机构轨读墙或新建验收机构来源。
- 用「有分馆 → 单一所在馆」覆盖订户机构合集。

### 3.4 菜单作用域

| scope | 读过滤 | 写前置 |
|-------|--------|--------|
| `subscriber` | 关联订户 | 须 **U1** |
| `institution` | 默认 `institutionId ∈ resolveSubscriberInstitutionIds()`；**订户/馆员列表**见 §4.2 例外 | 须 **U1**（订户/馆员列表例外允许 U0）；**新建验收**另须合集 **size === 1**；**新建/重新结算**另须所选验收单机构一致（见 §4.4） |
| `tenant` | 租户全局 | 按角色；**U0 仍不可进业务单据页**（订户/馆员列表除外） |

创建时写入 `institutionId` / `institutionCode`：

- **订户轨**：取所选/相关订户所属机构。
- **机构轨·验收单头**：取合集中**唯一**机构（size ≠ 1 则不可新建）。
- **机构轨·结算批次**：取所选验收单的共同机构（见 §4.4）。
- 编辑已有单据不改机构字段。

### 4.2 `institution` 轨

| 页面 | U0 | U1 读 | U1 写 | 数据权限范围 |
|------|----|-------|-------|-------------|
| 验收单管理 | 否/否 | 合集内 | 新建须合集唯一 | 读：`institutionId ∈` 合集；新建见 §4.4 |
| 待结算 | 否/否 | 同验收 | 新增结算见 §4.4 | 读与验收同口径；**新增结算**须所选验收单机构全部相同 |
| 已结算 | 否/否 | 同验收 | — | 读与验收同口径 |
| 结算失败 | 否/否 | 同验收 | 重新结算见 §4.4 | **重新结算**与新增结算同一机构一致性校验 |
| 订户列表 | **是/是** | 是 | 按角色 | **U0**：租户内**全部订户**（可新建/编辑）。**U1**：关联订户所属机构 → 这些机构下**全部订户** |
| 馆员列表 | **是/是** | 是 | 关联按角色 | **U0**：租户内**全部馆员**；「订户关联馆员」候选订户 = 租户**全部订户**。**U1**：关联订户所属机构 → **全部馆员**；候选订户 = 这些机构全部订户 |

### 4.4 验收 / 结算新建与验收域匹配

**新建验收单**（机构轨写）：

令 `ids = resolveSubscriberInstitutionIds()`：

| `ids.length` | 行为 |
|--------------|------|
| `0` | 不可新建（U0）；提示未关联订户 |
| `1` | 允许；写入该唯一机构的 `institutionId` / `institutionCode` |
| `> 1` | **报错，不可新建**；提示关联订户分属多个机构，请调整关联后再新建 |

不提供「从合集中手选机构」。多机构时**仍允许读**合集内历史验收单，仅禁止新建验收单。

**待结算 · 新增结算**与**结算失败 · 重新结算**（须 U1）：

对本次提交所涉及的验收单集合 `A`（待结算多选，或失败单关联/重选的验收单）：

1. `A` 非空；每张验收单须可读（`acceptance.institutionId ∈ resolveSubscriberInstitutionIds()`）。
2. 令 `inst =` 各验收单 `institutionId` 去重后的集合：
   - `inst.size !== 1` → **不可新增/重新结算**；提示所选验收单不属于同一机构。
   - `inst.size === 1` → 允许；结算批次写入该唯一 `institutionId` / `institutionCode`。
3. **不要求**账号订户机构合集 size === 1（与新建验收单不同）：合集含多机构的 U1，只要所选验收单同机构且该机构 ∈ 合集，即可结算。

**收货匹配**（逐条与批量，须 U1）：

```
可匹配 ⇔ 订单.subscriber ∈ 关联订户
      AND (订单.institutionId ?? 订户.institutionId) === acceptance.institutionId
      AND 头信息维度一致
```

验收单头不设订户字段；同机构内可跨订户收货（在关联订户与机构一致约束下）。

## 5. 落库、单号与历史

### 5.1 落库

| 实体 | 机构字段 | 赋值 |
|------|----------|------|
| 订单 / 订单行 | `institutionId`, `institutionCode` | 创建时取**所选订户**所属机构（订单行继承订单） |
| 验收单 | 同上；**无订户头字段** | 新建时合集唯一机构；编辑不改机构 |
| 催缺 / 换货 / 退货 | 同上 | 相关订户所属机构（订户轨） |
| 结算批次等 | 同上 | 所选验收单共同机构（新增/重新结算校验通过后写入） |

采访业务 UI 不展示机构列（只存）。

### 5.2 单号

与 10-15 相同：前缀为 `institutionCode`；流水键 `tenant + institutionCode + docType + date`；历史已发单号不改号。新建验收前缀 = 合集唯一机构的 code；结算前缀 = 所选验收单共同机构的 code。

### 5.3 历史补齐

存量缺 `institutionId`：沿用 10-15（单号前缀映射、或明细/订户机构补写）。补齐后机构轨过滤使用单据上的 `institutionId`。本修订不做 library 字段迁移。

## 6. 相对 10-15 / 10-21 变更清单

| 项 | 10-15 | 本文 |
|----|-------|------|
| 机构轨读墙来源 | 所在馆 → 单一机构 | 关联订户 → **机构合集** |
| 所在馆 | S1/S3 权限权威 | **非权限**；可展示 |
| 账号态 | S0–S3 | **U0 / U1**（无订户 / 有订户） |
| 旧 S1（有馆无订户） | 机构轨可用 | **U0**：无业务单据；可管租户订户/馆员并关联 |
| 旧 S2 机构轨 | 不可用 | **U1**，按合集可读 |
| 新建验收机构 | 创建人所在馆机构 | 合集**唯一**机构；多机构报错 |
| 新增/重新结算 | （随验收/所在馆） | 所选验收单须**同一机构**；批次写该机构；不强制账号合集唯一 |
| 逐条收货 | 仅 S3（隐含有馆） | **U1** 即可 |
| 订户列表 | S1 本机构全部；S3 仅关联 | **U0：租户全部订户可读写**；U1：关联订户所属机构 → **全部订户** |
| 馆员列表 | S1 本机构全部；S3 仅相关 | **U0：租户全部馆员可读写/关联**（候选=租户全部订户）；U1：关联订户所属机构 → **全部馆员**；候选=这些机构全部订户 |
| 机构轨空态文案 | 无所在馆 | **未关联订户**（订户/馆员列表除外） |
| 首个 U1 | S1 可关联本机构订户 | U0 管订户 + 馆员关联 → 目标账号变为 U1 |
| 验收单头订户字段 | 无 | **仍无** |
| library 主轴（10-21） | 并列备选 | **仍未采用** |
| 导入模板 | 配置与选用同一套订户过滤 | **配置页**租户有菜单者全可见；**订单选用**才按未绑/已绑订户规则 |

## 7. 空态与提示

| 条件 | 行为 |
|------|------|
| U0（订户列表 / 馆员列表） | 可加载租户全部订户/馆员并按角色写入与关联 |
| U0（其它业务轨） | 提示：当前账号未关联订户；无业务数据 |
| U1 订户轨 | 按关联订户正常加载 |
| U1 机构轨读 | 按订户机构合集加载 |
| U1 新建验收且合集 size ≠ 1 | 报错：关联订户分属多个机构，请调整关联后再新建 |
| U1 新增/重新结算且所选验收单机构不一致 | 报错：所选验收单不属于同一机构 |

| `resolveLibrarianListScope` | U0 → 租户全部馆员（关联候选=租户全部订户）；U1 → 关联订户机构下全部馆员（候选=这些机构全部订户） |
| `filterImportTemplatesForConfigPage` | 租户全量（调用方已做菜单/角色）；不按订户过滤 |
| `filterImportTemplatesForOrderSelect` | 须 U1；未关联订户的模板全 U1 可见；已关联订户的模板按关联交集过滤 |

验收匹配伪码见 §4.4。

## 9. 测试要点

1. U0：订户/馆员列表可见可写租户全量，并可完成关联；其它业务页无数据、不可写；提示未关联订户。  
1b. 引导：U0 将订户关联到某馆员后，该馆员变为 U1，业务读墙随即按合集生效。  
2. 单机构、多关联订户：机构轨可见该机构验收/结算/馆址/条码；可新建验收；订户/馆员列表为该机构全部。  
3. 跨两机构关联订户：机构轨可读两机构单据；新建验收报错；若勾选跨机构验收单则新增/重新结算报错；勾选同一机构验收单则可结算。  
4. 有所在馆 vs 无所在馆、同一关联订户集：读墙与新建行为一致。  
5. U1 逐条收货与批量验收：按关联订户 + 机构一致可匹配。  
6. 导入模板：配置页租户内有菜单权限者均可见；订单管理选用时，绑定订户 A 后仅关联 A 的 U1 可选，未绑定订户则租户内 U1 均可选。  
7. 历史单号不改；补 `institutionId` 后机构过滤生效。
