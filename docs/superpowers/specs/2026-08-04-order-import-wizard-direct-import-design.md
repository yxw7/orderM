# 导入订单向导 — 第 2 步直接入库设计

**日期**：2026-08-04  
**状态**：待实现  
**模块**：非连续出版物订单 / 订单列表 / 导入订单  
**关联**：现有三步向导 `ImportOrderModal.vue`；PRD `5.2.5.6 导入订单`

---

## 1. 背景与目标

当前导入订单为三步向导：上传 → 解析 → 入库。用户在第 2 步点「下一步」进入第 3 步后，还需再点「入库」才执行数据写入，多一次确认点击。

### 1.1 目标

- 第 2 步主按钮由「下一步」改为「导入」
- 点击「导入」后直接进入第 3 步并自动执行入库，无需再点「入库」
- 保留三步步骤条与第 3 步 loading / 成功 / 失败结果展示

### 1.2 非目标

- 不压缩为两步向导
- 不修改入库业务规则（`applyOrderImport`、订单状态待导入→待发订、写入订单行）
- 不修改上传校验、解析模拟、下载解析结果等能力
- 不改结果文案（仍用「入库成功」「入库失败，请联系管理员」）

---

## 2. 方案

**保留三步，合并操作（已选）**

步骤条不变：① 上传文件 → ② 解析文件 → ③ 数据入库。  
仅将「进入第 3 步」与「执行入库」合并为第 2 步的一次「导入」点击。

---

## 3. 交互

| 步骤 | 内容 | 主按钮 | 行为 |
|------|------|--------|------|
| 1 | 选模板、上传 xls/xlsx | 上传 | 校验通过后解析并进入第 2 步（不变） |
| 2 | 展示解析成功/失败数；可下载解析结果 | **导入** | 仅 `canProceed`（全部成功）可点；点击后 `goStep(3)` 并立即 `handleImport` |
| 3 | loading → 成功 / 失败 | 成功：关闭；失败：取消关闭 | 入库由第 2 步触发；本步不再展示「入库」按钮（失败亦不可重试入库，需关闭后重新打开向导） |

### 3.1 文案约定

| 位置 | 文案 |
|------|------|
| 第 2 步主按钮 | 导入 |
| 第 2 步提示 | 解析全部成功，才可入库（不变） |
| 步骤条第 3 步 | 数据入库（不变） |
| 成功 | 入库成功 |
| 失败 | 入库失败，请联系管理员 |

### 3.2 禁用规则

解析存在失败行时「导入」置灰、不可点（与原「下一步」相同，依据 `parseResult.canProceed`）。

---

## 4. 实现要点

- 主改文件：`html/src/modules/order/components/ImportOrderModal.vue`
  - 第 2 步按钮文案：`下一步` → `导入`
  - 点击处理：由仅 `goStep(3)` 改为进入第 3 步并调用现有 `handleImport`
  - 移除第 3 步「入库」按钮分支（`currentStep === 3 && importStatus !== 'loading'` 的入库按钮）
- 业务：`order-import.js` 的 `applyOrderImport` / 父组件 `@import` 处理逻辑不变
- 文档同步：`docs/prd.md`、`html/src/prd/order-manage-prd-data.js` 中 5.2.5.6 描述改为「第 2 步点导入即入库」

---

## 5. 验收

1. 解析全部成功时，第 2 步显示可点的「导入」
2. 点击「导入」后进入第 3 步并出现 loading，随后「入库成功」，订单变为待发订
3. 第 3 步成功态不出现「入库」按钮，仅「关闭」
4. 解析有失败时「导入」置灰，无法进入入库
5. 入库失败时展示「入库失败，请联系管理员」，页脚仅「取消」；需关闭后重新打开向导再导入
