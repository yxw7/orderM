## 1. 背景与目标

发货单收货套数常大于订单行待收。产品要求：

- **不算校验失败**，仍可入库
- 草稿套数按 **待收** 截断存储
- 失败数据导出中仍带出该发货单行的超收异常说明
- 第 3 步汇总保持 **成功 / 失败** 两态，成功侧旁注「含 M 条超收」（不单独做成第三种结果状态）

### 1.1 目标

- 行级：`result` 仍为「通过」+ `qtyOverPending` 标记（方案 1）
- 汇总：`X 条成功（含 M 条超收）` / `Y 条失败`
- 入库：全部「通过」行（含超收）
- 下载：失败行 ∪ 超收行，同一「下载解析结果」按钮

### 1.2 非目标

- 不把「超收」提升为与「通过」「失败」并列的第三种 `result`
- 不分两个下载按钮
- 不改批验收（`mode !== 'precheck'`）下＞待收仍为「套数非法」
- 不改逐条收货处置弹窗校验（仍受待收上限约束；带入值已是待收）

---

## 2. 已确认产品选择

| 问题 | 选择 |
|------|------|
| 超收是否入库 | 与成功一样入库（按待收写草稿） |
| 汇总展示 | 两态：成功 / 失败；成功旁注「含 M 条超收」 |
| 下载 | 失败与超收同一文件导出；有失败或超收时显示按钮 |
| 行级模型 | 方案 1：`通过` + `qtyOverPending`，不单独 `result=超收` |

---

## 3. 行级校验（仅预验收 `precheck`）

已匹配且头属性一致后：

| 条件 | `result` | 其它 |
|------|----------|------|
| 收货套数 ≤ 0 | 套数非法（失败） | 原因：`套数 ≤ 0` |
| 收货套数 ＞ 待收 | **通过** | `qtyOverPending=true`；原因文案：`套数大于待收（发货单 n/待收 m）`；`receiveSets` / `fieldValues.receiveQty` 截断为待收 |
| 0 ＜ 套数 ≤ 待收 | 通过 | 无超收标记 |

并存规则：

- 若同行另有「不一致」等真正失败：以失败 `result` 为准；可保留超收标记；导出时超收文案与失败原因用「；」拼接
- 收货套数不走「不一致」比对

批验收等 `mode !== 'precheck'`：＞待收仍记「套数非法」。

---

## 4. 第 3 步汇总与操作

计数：

- `X`（成功）= `result === '通过'` 的行数（**含**超收）
- `M`（超收）= 通过且 `qtyOverPending` 的行数
- `Y`（失败）= 非通过行数

展示：

- 无超收：`共校验到 N 条数据，其中 X 条成功，Y 条失败。`
- 有超收：`…其中 X 条成功（含 M 条超收），Y 条失败。`
- 灰色提示：「下载解析结果」会一并导出超收行。

交互：

- 橙色提示：`点击「下一步」按钮，只导入成功行，不导入失败行。`（超收已计入成功）
- 「下一步」：`X > 0` 可用；`X = 0` 置灰
- 「下载解析结果」：`Y > 0` 或 `M > 0` 时显示
  - 导出集合：失败行 ∪ 超收行（`sourceRow` 保留发货单原始套数）
  - 列：原发货单列（原顺序）+ 失败原因
  - 超收原因：`套数大于待收（发货单 n/待收 m）`

---

## 5. 第 4 步入库与草稿

- 入库范围：全部 `result === '通过'`（含超收）
- 草稿维度不变：验收单号 + 订单行号
- `receiveSets` / 映射值中的收货套数：存截断后的待收，**不是**发货单原套数
- 逐条收货带入：继续读草稿套数（已是待收）

---

## 6. 文案与 PRD 同步点

- 校验规则「i」：字段校验；强制校验（订单行号/收货套数默认开启不可取消；≤0 套数非法；超出待收不失败、按待收存储并归入异常导出）；ISBN/ISRC 去空格与「-」；数据错误；未匹配；验收单不匹配
- 「套数非法」判定条件仅保留 ≤0（预验收）
- 演示文件名含「超收」：应计成功（含超收旁注），可下载异常，入库套数为待收

## 8. 测试要点

| 场景 | 期望 |
|------|------|
| 仅超收、无其它失败 | 成功=N（含 N 超收）、失败=0；可下一步；可下载；草稿套数=待收 |

| 无失败、无超收 | 不显示下载按钮；成功文案无「含超收」 |
